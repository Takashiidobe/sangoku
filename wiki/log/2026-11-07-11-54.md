# Narrow signed division overflow (sangoku-7qz.22)

_2026-11-07 11:54:59_

## Context

`sangoku-7qz.22` (P3): i8/i16 `sdiv`/`srem` widen to i32 and call
`__gbc_sdiv32`, so `MIN / -1` returned the wrapped value instead of trapping as
CLIF specifies (i32 already trapped). Rust emits its own overflow check first,
so `core` was unaffected; this was about exact CLIF semantics.

## Case

```text
sdiv.i8  -128, -1   ; should trap, returned wrapped -128
sdiv.i16 -32768, -1 ; same
```

The ticket also claimed `srem` was wrong, but CLIF `srem(MIN, -1)` returns zero,
so the premise was incorrect and that behavior is preserved.

## Cause

The i32 helper computes a quotient that does not fit the narrow type; nothing
checked that it fit after the call.

## Fix

Check that an i8/i16 signed quotient fits after the i32 helper call, trapping
otherwise. Regression `signed_division_overflow_and_remainder_follow_clif` runs
bounded none/speed emulator checks across i8/i16/i32 for overflow, zero
divisors, remainder and valid neighbouring boundary results. Updated the
lowering concept documentation. Rebuilt cg_clif; blank-ROM smoke check, clippy
and fmt pass. Full `cargo nextest run --no-fail-fast`: 110 passed, 0 skipped.
Backend fix committed as wasmtime `50f95fb9`; no push.
