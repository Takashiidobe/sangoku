# Retain build artifacts and investigate sort size (sangoku-xn2)

_2026-11-07 17:27:06_

`sangoku-xn2` asked the `sort` example to use direct bounded integer and array
serial output instead of general `core` formatting, so it would link and run in
a 32 KiB ROM. To see why ROMs were too big, build and CLIF invocations now
retain intermediates in `build/artifacts` named with source name, PID and
timestamp. The path is printed before compilation; successful ROM links also
save `game.map` and `game.sym`. Verified artifacts survive both a successful
`primes` run and a failed `sort` link.

Finding: `sort` now uses direct serial output, but `sort_unstable` still retains
`panic_bounds_check` through heapsort and `slice::swap`, which retains `core`
formatting. The runtime helpers total 1301 bytes. Sorting still does not fit at
opt-level `0` or `z`; `sangoku-xn2` remains open.
