# Shared f64 arithmetic runtime (sangoku-7qz.9.4.1)

_2026-11-07 08:19:34_

## Context

`sangoku-7qz.9.4.1` (P0): split f64 could be moved around but not computed on.
Expanding binary64 arithmetic inline per call site would blow the 32 KB ROM, and
f32 arithmetic is not enough for f64 precision or range. So f64 uses one shared
runtime called through a memory ABI. Runtime total: 5362 bytes for the complete
operation set.

## Case

f64 add/sub/mul/div, min/max, all `FloatCC` comparisons, sqrt, fused
multiply-add and integral rounding. Fixture
`tests/fixtures/emulate/softfloat-f64.clif`; Rust `examples/f64.rs` (f64
addition).

## Before

Only transport and sign operations lowered (`sangoku-7qz.9.4`).

## After

Standalone unoptimized add/FMA caller sizes: 1440/1992 bytes (the cost of
split-value loads, context copies, stack addressing and spills). 468 bounded
host-kernel checks passed; all 105 nextest tests pass. f64 and blank ROM builds
pass.

## How

- Caller fills a 34-byte stack context (three 8-byte operands, an 8-byte result,
  opcode, comparison mask) and calls the shared helper. No global scratch state,
  so it is reentrant.
- `runtime/softfloat64.c` uses stack-local 128-bit byte-array significands,
  exact 106-bit products and round-to-nearest ties-to-even; FMA rounds once.
- Compiled by SDCC SM83 to checked-in RGBDS `runtime/softfloat64.asm` via the
  reproducible `tools/generate_softfloat64.py`; normal builds need no C
  compiler.
- Enabled f64 frontend functions and the runtime libcall; f64-only ROMs omit the
  f32 runtime.
- Bounded none/speed emulator edge cases, source-hash and size guards. Rebuilt
  cg_clif; clippy, fmt, generator `--check` and LSP checks pass. Updated
  generated coverage and concept docs.

## Alternatives

Not done: caller-size reduction is `sangoku-7qz.9.9`; numeric conversions remain
`sangoku-7qz.9.7`.
