# Memory offsets and narrow loads/stores (sangoku-7qz.21)

_2026-11-06 22:30_

## Context

The matrix showed `load`/`store` with offset 300 unsupported at every width:
`lower.rs` bailed whenever the offset was outside -128..127. `uload8`/`uload16`
and `istore8`/`istore16` were unsupported too. These are needed for struct field
access past 127 bytes and for the narrow memory ops `cg_clif` emits for `u8`/
`i16` fields. sangoku-7qz.21 (P0) asked for matrix rows `load.offset`, `uload*`,
`sload*`, `istore*` to be `ok`, with emulator round-trips at offsets 0, 127,
128, 300 and negative.

## Case

Load or store at an offset like 300 or -200 from a pointer; `u8` loaded as
wider, or the low bytes of a wider value stored.

## Before

`lower.rs` bailed as unsupported for offsets outside -128..127; narrow forms had
no arm. Exact error text: not recorded.

## After

Matrix regenerated: `load.offset`, `uload*`, `istore*` ok.

## How

- `fold_offset` in the `lr35902` lowering adds an out-of-range offset to the
  address with `Add16` and then uses offset 0, instead of bailing. The old
  inc/dec-`hl` sequence is kept for small offsets only.
- `Load`/`Uload8`/`Uload16` and `Store`/`Istore8`/`Istore16` share one arm;
  `i32` and narrow forms go byte by byte with fresh scratch regs (see
  sangoku-7qz.16), full-width `i16` keeps `LoadMem16`/`StoreMem16`.
- `uload` zero-fills upper bytes; `istore` stores the low bytes of the wider
  value.
- Test: `tests/lowered.rs` `memory_offsets_beyond_a_signed_byte` runs 8
  functions in the emulator (offsets 126-128, 300, -5, -200).

## Alternatives

Not done: `sload8`/`sload16` remain unsupported here; they need sign fill, noted
on sangoku-7qz.3.
