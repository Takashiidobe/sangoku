# Cranelift 903832fa — Run LR35902 functions through Cranelift compilation

_2026-11-05 09:10:14_

## Context

`compile_function` on the LR35902 ISA returned `Unsupported` unconditionally, so
every function was rejected before lowering and lowering gaps could not be seen.
Commit `903832fa` (Cranelift fork, `third_party/wasmtime`) connects the target
to the standard machine-backend pipeline. No bead id is recorded.

## Case

Compiling any CLIF function failed immediately.

## Before

```text
CodegenError::Unsupported("LR35902 function lowering is not implemented")
```

## After

`isa/lr35902/mod.rs` builds the signature set and callee state, runs the machine
compiler and emits:

```rust
let sigs = SigSet::new::<abi::LR35902ABIMachineSpec>(func, &self.flags)?;
let abi = Callee::<abi::LR35902ABIMachineSpec>::new(func, self, &self.lr35902_flags, &sigs)?;
let vcode = compile::<Self>(func, domtree, regalloc_ctx, self, abi,
    emit_info, sigs, ctrl_plane)?;
let emit_result = vcode.emit(&regalloc_ctx.output, want_disasm, &self.flags, ctrl_plane)?;
```

## How

`compile_function` now constructs `SigSet` and `Callee`, calls
`machinst::compile`, and emits through the register-allocation context. The
returned stencil carries emitted bytes, disassembly, block offsets and
value-label ranges. Lowering still had holes (placeholders stay explicit); they
now show up as unsupported instructions instead of blanket rejection.

## Alternatives

None recorded. Later instruction-lowering commits produce machine code through
this standard Cranelift path.
