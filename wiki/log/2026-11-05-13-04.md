# rustc_codegen_cranelift 8e2bcf1 — Skip float routines for LR35902

_2026-11-05 13:04:22_

## Context

`core` and compiler-builtins contain many float-bearing functions that an
integer-only game never calls, but the backend cannot lower them and would stop
on the first one. Skipping them lets `core` compile; user code that uses floats
must still fail loudly instead of silently miscompiling. Commit `8e2bcf1` in
`rustc_codegen_cranelift`; no bead.

## Case

Any monomorphized function with a floating-point local, e.g. `f32` or `f64`
routines in `core`.

## Before

Such functions reached predefinition and codegen, which has no float support.

## After

In `core` and compiler-builtins they are skipped; in user crates:

```text
floating-point operations are not supported on the LR35902 target
```

## How

`has_lr35902_float_mir` in `src/driver/mod.rs` checks monomorphized local
declaration types with `ty.is_floating_point()`, active only for
`Arch::Other("z80")`. `predefine_mono_items` skips matches, and
`src/driver/aot.rs` `continue`s for `core`/compiler-builtins or calls
`span_fatal` for user crates.

## Alternatives

Adding software float operations and runtime helpers was not done; omission is a
deliberate strategy that enables progress on integer-only `core` use, and float
code remains explicitly unsupported.
