# Cranelift 0b6e1092 — Align stack slots to words

_2026-11-05 12:29:14_

## Context

The backend started from a generic Z80 scaffold whose `stack_align` returned 1
("no specific stack alignment requirements"). Frame layout then ignored
word-sized stack behavior and backend assumptions about 16-bit slots. Commit
`0b6e1092` in Cranelift (`third_party/wasmtime`); no bead.

## Case

Any frame computed through Cranelift's frame-layout logic for the Fast
convention.

## Before

```rust
fn stack_align(_call_conv: isa::CallConv) -> u32 { 1 }
```

## After

```rust
fn stack_align(_call_conv: isa::CallConv) -> u32 { 2 }
```

## How

`abi.rs` returns a two-byte boundary. The ABI test
`byte_abi_assigns_arguments_and_returns_in_documented_register_order` now also
asserts `stack_align(CallConv::Fast) == 2`.

## Alternatives

Generic byte alignment from the Z80 scaffold was rejected in favour of a
target-specific word rule.
