# Evaluate emulator-backed runtime tests

_2026-11-06 08:53_

Bookkeeping, investigation. The `tests/test_mul16.py` instruction interpreter
only covers the instructions the runtime uses, so I looked at replacing it with
a real emulator. No Bead created, as requested; no test implementation changed.

SameBoy provides a library build and public APIs for ROM loading, mutable CPU
registers, memory access, and execution with elapsed 8 MHz ticks. A small native
runner can initialize arguments and a return sentinel, run until the sentinel,
then report the result, restored `SP` and accumulated time. Timing units must be
converted explicitly for normal versus double-speed CGB operation.

PyBoy offers Python register/memory access and address hooks, but its public
tick API advances frames. Its current source exposes cycle counting as private
`_cycles()`, so precise timing would depend on a pinned private API.

Sources: https://github.com/LIJI32/SameBoy/wiki/GB_run,
https://raw.githubusercontent.com/LIJI32/SameBoy/master/Core/gb.h,
https://docs.pyboy.dk/_modules/pyboy/pyboy.html.

Recommendation: a reusable SameBoy library runner, with no emulator fork (not
implemented). Checks: `cargo clippy --allow-dirty --fix` and `cargo fmt` passed.
