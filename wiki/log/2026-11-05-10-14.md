# Cranelift e5ff9920 — Add assembly object-module support

_2026-11-05 10:14:37_

## Context

Cranelift's `ObjectModule` manages functions and symbols but serializes a native
object file; for this target RGBDS owns assembly and linking, so there is no
native object encoding. Commit `e5ff9920` (Cranelift fork,
`third_party/wasmtime`) adds a builder for callers that emit assembly. No bead
id is recorded.

## Case

The rustc backend wanted to keep Cranelift's module interface but could not
construct an `ObjectModule` for an architecture the `object` crate does not
know.

## Before

No assembly-only way to build the module.

## How

`cranelift/object/src/backend.rs` (+26 lines) extends the object backend with an
assembly module implementation that accepts generated functions and symbols
without requiring a native object encoding.

## Alternatives

Rather than inventing a parallel function-registration layer for text output,
this keeps Cranelift's symbol/function management and module interfaces while
RGBDS owns final assembly and linking.
