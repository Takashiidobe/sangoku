# Separate core and alloc fixture dependencies (sangoku-vmq)

_2026-11-08 07:03:05_

## Context

Since 940841a, every `sangoku` build/clif/frontend invocation passed
`--extern force:gbc_heap`, so 9 nextest tests failed. sangoku-vmq (P1 bug) asked
to force the heap crate only for programs that use alloc.

## Case

`#![no_core]` fixtures (`tests/fixtures/programs/*.rs`) failing with `E0152`
duplicate lang item `sized`: `rust_f128_arithmetic`, `f128_memory`,
`f64_memory_add`, `numeric_conversions`, `u128_memory_add`, `u64_memory_add`,
`usize_and_pointer_offsets` (lowered), `fixtures_match_filecheck_expectations`
(filecheck) and `link::tests::exported_runtime_entries_select_their_objects`
(bin).

## Cause

`CoreLibraries::externs(4)` passed `--extern force:gbc_heap` to every
invocation, so `no_core` fixtures collided on the `sized` lang item.

## Fix

- Program fixtures moved to `tests/fixtures/core/programs`; new
  `tests/fixtures/alloc/heap.rs`.
- Default build/frontend/clif commands expose `core` and `compiler_builtins`
  only; `--alloc` adds `alloc` and forces `gbc_heap`. Core ROM linking omits
  alloc/heap assembly.
- Fixed runtime object selection for `__gbc_heap_init`.
- Refreshed 26 stale MIR/CLIF expectations against the current toolchain; only
  generated checks changed.
- Validation: full nextest ran 171 tests (169 passed; stale FileCheck and the
  heap selector failed); after fixes all 17 CLI/link/example/FileCheck tests
  passed. Clippy, fmt, diff check and LSP diagnostics passed. Hello ROM links;
  `examples/heap.rs` links with `--alloc --opt-level z`.

## Alternatives

Not done: default optimization for `examples/heap.rs` exceeds the 32 KiB ROM
capacity, so it only links at opt `z`. No `third_party` changes, no push.
