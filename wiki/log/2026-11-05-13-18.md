# Cranelift a082e072 — Treat stack addresses as register computations

_2026-11-05 13:18:28_

## Files and implementation

`cranelift/codegen/src/isa/lr35902/inst/mod.rs` removes stack-address
calculation from the instruction's memory-access classification:

```diff
-| Inst::StackAddr16 { .. }
```

`StackAddr16` computes a pointer into registers; it does not read or write
memory. Marking it as a memory access could make scheduling/dependence logic
treat address formation like a load/store and constrain unrelated operations.
The address-generation code from the previous commit is unchanged.

Commit: `a082e072` — Cranelift (`third_party/wasmtime`). Purpose: Avoid
classifying stack-address formation as a memory access. Change: Removed
`StackAddr16` from the machine instruction memory-access classification.
Implementation: The instruction still computes the stack address in registers;
the change keeps memory-dependence handling from treating address calculation
itself as a load or store. Design note: This is a scheduler/alias classification
correction to the preceding `stack_addr.i16` lowering, not a new
address-generation sequence.
