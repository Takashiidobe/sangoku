# Cranelift a082e072 — Treat stack addresses as register computations

_2026-11-05 13:18:28_

## Context

Right after `StackAddr16` landed (80241cb8), it was listed in the instruction's
memory-access classification. Commit `a082e072` in Cranelift
(`third_party/wasmtime`); no bead.

## Case

Any `stack_addr.i16` lowered to `StackAddr16`.

## Cause

`StackAddr16` only computes a pointer into registers (`ld hl, sp + n`); it does
not read or write memory. Listing it in `is_mem_access` could make
scheduling/dependence logic treat address formation like a load/store and
constrain unrelated operations. No failing output was recorded.

## Fix

```diff
-| Inst::StackAddr16 { .. }
```

removed from `is_mem_access` in `cranelift/codegen/src/isa/lr35902/inst/mod.rs`.
The address-generation code is unchanged. No new test.

## Alternatives

This is a classification correction to the preceding `stack_addr.i16` lowering,
not a new address-generation sequence.
