# Organize independently selected runtime libraries (sangoku-7u5)

_2026-11-08_

Bookkeeping/reorganization. `sangoku-7u5` (P2) asked to split runtime linkage
into selectable operation units and organize integer, bitshift, float and memory
helpers under family directories with dispatch and size/speed variants,
preserving existing ABIs and validating isolated helper selection and ROM
execution, so a ROM links only the helpers it uses.

- Moved registered runtime routines into `integer`, `bitshift`, `float` and
  `memory` directories. Family registries under `src/runtime` supply stable
  object names, source paths and dependency text. Linkage selects size variants
  at `s`/`z`, speed variants at `0`/`1`/`2`/`3`, and common implementations at
  every level. Native integer width paths use `i8`/`i16`/`i32`; existing wider
  support is retained. No new native-width arithmetic algorithms or ABI changes.
- Split `udiv16`/`urem16` wrappers from the shared division core. Combined code
  remains 95 bytes with unchanged measured cycles; selecting either entry now
  excludes the other wrapper. Assembly audit helpers combine the three sources
  when they need both public entries.
- Split the hand-written `f32` library into separate operation and shared-helper
  objects. Fallthrough labels are kept together, cross-object dependencies are
  exported, and absolute jumps are used between independently placed sections.
  Shared macros and scratch state remain common, macro definitions are visible
  to dependency discovery, and existing non-reentrant scratch behavior is
  unchanged.
- A real Rust `f32` addition ROM executes at opt `0`/`z` and its map excludes
  multiply, divide, square root, FMA, rounding and comparison entries. Existing
  float reference tests exercise the aggregate; production linkage uses only
  selected objects. Tests and generators use the new paths, bundle packaging
  copies nested assembly/includes, and generated float assembly was regenerated
  and checked.
- Validation: 177 default nextest tests pass, 17 profile exclusions. Four
  affected extensive tests pass: `f16_fma_matches_reference`,
  `f64_shared_runtime_matches_host`, `f128_shared_runtime_matches_reference` and
  `wide_numeric_conversions_match_reference`. Hello ROM build,
  `cargo clippy --allow-dirty --fix`, `cargo fmt`, LSP error diagnostics and
  `git diff --check` pass. No vendored compiler/backend sources changed.
  Pre-existing local edits are preserved.
- Follow-ups: `sangoku-rxd` separates operations behind `f64`/`f128` and wide
  conversion operation-code dispatchers (not done). Existing native-width
  popcount work remains `sangoku-4gv`. `sangoku-fx7` audits CLZ/popcount
  candidates and whether they need wiring.
