# Cranelift 9ba3bea9 — Lower symbol-valued constants

_2026-11-05 14:15:04_

## Context

Compiler-generated library code needs to materialize a function or data address
as a value (a vtable entry, a function pointer, a static's address). The
`lr35902` backend had no lowering for `Opcode::SymbolValue`, so that code could
not be compiled. Commit `9ba3bea9` in Cranelift (`third_party/wasmtime`).

## Case

A CLIF `symbol_value` producing an `i16` (a symbol address plus addend).

## Before

No lowering for `SymbolValue`; compilation of any function taking a symbol's
address failed. Exact error text: not recorded.

## After

```asm
ld hl, <symbol>+<addend>   ; 16-bit absolute relocation, resolved at link time
```

then the bytes are copied from `HL` to the allocated result registers.

## How

- `isa/lr35902/lower.rs` handles `Opcode::SymbolValue` when the result is `I16`,
  extracting the symbol and addend from `GlobalValueData::Symbol` and emitting
  an `Inst::LoadSymbol16`.
- `inst/emit.rs` emits `ld hl, imm16` (`0x21`) and records the relocation with
  `sink.add_reloc_at_offset(reloc_offset, Reloc::Abs2, name, *offset)`.
- The downstream assembler/linker resolves the `Abs2` relocation.

## Alternatives

Tradeoff: the 16-bit relocation matches the Game Boy address space, so wider
pointer representations are unsupported.
