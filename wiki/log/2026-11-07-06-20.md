# Fused multiply-add for f32/f16 (sangoku-7qz.8.6)

## Context

`sangoku-7qz.8.6` (P2, under the f16/f32 float epic `sangoku-7qz.8`) was the
last missing float op in the f16/f32 matrix: `fma` showed `-` (unsupported) in
`tests/coverage/lower.md`. `fma` must round once, so `a*b + c` built from the
separate multiply and add helpers would round twice. Result: the matrix goes
from `ok 242 / unsupported 322` to `ok 244 / unsupported 320`; f16/f32 now has
no unsupported ops except the i64/f64/f128 cases.

## Case

```text
v4 = fma v1, v2, v3     ; f32 and f16 operands loaded from memory
```

Fixtures: `%ffma` in `tests/fixtures/emulate/float-arith.clif` and `%h_ffma` in
`float-convert.clif`.

## Before

`fma` row in the coverage matrix: `| fma | - | - | - | - |`.

## After

`| fma | ok | ok | - | - |`; `README.md` lists `fma` among supported ops.

## How

- `__gbc_ffma32(a, b, c, odd)` in `runtime/softfloat32.asm`: exact 48-bit
  product (mul loop extracted into `sf_mul48`, shared with fmul) placed in a
  64-bit field with the 24-bit addend aligned to it. The smaller operand is
  shifted right with jamming, then add or subtract, normalize to bit 63, jam
  into `wM` and use `sf_roundpack`.
- Special cases: NaN, inf\*0, inf-inf, zero product (signed zero rules); exact
  cancellation gives +0.
- f16 fma passes `odd=1`: the f32 result is rounded to odd (low 7 guard bits
  collapsed into bit 7) so the following demote to f16 does not double round.
  Disabling it makes the f16 test fail.
- Tests: `f32_fma_matches_host` (edge triples + 500 random with exponents near
  cancellation) vs `f32::mul_add`; `f16_fma_matches_reference` (all sample
  triples) vs f64 `mul_add` + brute-force f16 rounding. Sabotaged both.

## Alternatives

None recorded. The f16/f32 coverage matrix now has no unsupported ops except the
i64/f64/f128 cases.
