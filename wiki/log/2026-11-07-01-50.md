# f32/f16 as byte-register types (sangoku-7qz.8.1)

_2026-11-07 01:50_

## Context

Floats were entirely unsupported. Rather than add a float register class to a
backend with only byte registers, sangoku-7qz.8.1 (P0) maps `f32` onto the `i32`
parts and `f16` onto the `i16` parts so moves, spills, ABI, load/store, select
and call work unchanged, and does the sign-bit-only ops inline with no libcalls.
It is the base for the soft-float work in 8.2-8.5.

## Case

`f32`/`f16` values moved, loaded, stored, selected, bitcast, negated, abs'd or
copysign'd, and `f16const`/`f32const`.

## Before

Every float op unsupported in the matrix.

## After

Matrix: `f32` `call`, `f.const`, `fabs`, `fcopysign`, `fneg`, `load`, `select`,
`store` now ok.

## How

- `rc_for_type`: `F32` shares the `I32` byte parts, `F16` the `I16` parts, so
  spills, the ABI (including stack returns), call and return need no float
  class.
- Lowering: load/store/select accept `F16`/`F32`; `f16const`/`f32const` load the
  bit pattern; same-size bitcast is per-byte moves; `fneg`/`fabs`/`fcopysign`
  touch only the top byte (`xor 0x80`, `and 0x7f`, merge sign).
- Test: `fixtures/emulate/float-bits.clif` + `lowered.rs`
  `f32_sign_ops_select_and_const_match_host` (NaN, inf, +-0, subnormal, MAX
  against host bits).

## Alternatives

`f16` shares the code paths but has no dedicated runtime test. Arithmetic,
`fcmp` and conversions remain for 8.2-8.5.
