# rustc_codegen_cranelift 3a8531a — Align fork with local Cranelift

_2026-11-05 08:47:22_

## Context

The rustc backend (`third_party/rustc_codegen_cranelift`) depended on released
Cranelift crates, which do not contain the in-progress LR35902 ISA. Commit
`3a8531a` makes it build against the local Cranelift fork. No bead id is
recorded.

## Case

The backend could not even request the `lr35902` feature from a registry
release.

## Before

```text
cranelift-codegen = { version = "0.137.0", ... }
```

## After

```diff
-cranelift-codegen = { version = "0.137.0", ... }
+cranelift-codegen = { path = "../wasmtime/cranelift/codegen", ...,
+    features = ["std", "timing", "unwind", "all-native-arch", "lr35902"] }
```

## How

Replaced released Cranelift dependencies with sibling checkout paths and enabled
the LR35902 feature in `Cargo.toml` and `Cargo.lock`. `src/vtable.rs` was
adjusted for a changed `MemFlagsData` API in current Cranelift main.

## Alternatives

Registry releases lack the in-progress target, so local paths let development
proceed against the fork immediately. The next commit (`d03fa6e`) changed this
to a git branch dependency.
