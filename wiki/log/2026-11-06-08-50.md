# Migrate 16-bit multiplication (sangoku-9ud)

_2026-11-06 08:50_

## Context

sangoku-9ud (P1 bug): `runtime/mul16.asm` treated `B` as lhs high and `C` as lhs
low, but the backend ABI assigns lhs low to `B` and high to `C`. rhs low arrives
in `A` and high at `[SP+2]`, yet the helper loaded them into `D` and `E`
respectively. Under the ABI `1 * 1` returned 0, and the only backend test
checked call emission, not results. Found by the comparison in sangoku-xtm.

## Case

```rust
let r = a.wrapping_mul(b); // u16, any non-symmetric byte values
```

## Cause

Operand packing at the entry of `__gbc_mul16` disagreed with the ABI, as above.

## Fix

Replaced the helper with the ABI-adapted MSB-first shift-and-add port. Entry
repacks the operands (before: `ld d, a` / `ld e, a` from `[SP+2]`, 16 fixed
iterations, `srl d`/`rr e` on rhs and `sla c`/`rl b` on lhs):

```asm
ld d, c
ld e, b
ld c, a
ld hl, sp + 2
ld a, [hl]
ld hl, 0
ld b, 16
or a
jr nz, .bit
ld b, 8
ld a, c
```

It runs eight iterations when rhs < 256 and sixteen otherwise. Size is 30 bytes;
timing including `RET` is 480 + 4p or 848 + 4p clocks, `p` the rhs population
count. Result returns in `A`/`B` (low/high). Closed sangoku-9ud.

Added `tests/test_mul16.py`, which assembles the actual helper with RGBDS and
executes its bytes in a small instruction interpreter, not a full emulator:
10,256 boundary, signed, asymmetric-byte and random product pairs plus five
timing cases. `README.md` documents arithmetic support and the test command.

Passed: Python regression tests, Ruff checks/format, `cargo test --bins`,
`cargo clippy --allow-dirty --fix`, `cargo fmt`, `git diff --check`, and ROM
smoke `cargo run -- build examples/blank.rs build/blank.gb`.

## Alternatives

Plain `cargo test` fails because the existing `no_core` example has no host
`main`. No compiler or vendored source changes; existing vendored warnings
remain.
