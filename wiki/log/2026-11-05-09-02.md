# Cranelift 43f09482 — Put LR35902 byte registers in regalloc

_2026-11-05 09:02:15_

## Files and implementation

Changes are in `cranelift/codegen/src/isa/lr35902/inst/regs.rs`, `abi.rs`,
`inst/mod.rs`, and `inst/emit.rs`. The allocator sees only the seven real byte
registers; a move is now a modeled instruction rather than a placeholder:

```diff
+pub(crate) const fn allocatable_int_regs() -> PRegSet {
+    PRegSet::empty().with(preg(Gpr8::B)).with(preg(Gpr8::C))
+        .with(preg(Gpr8::D)).with(preg(Gpr8::E))
+        .with(preg(Gpr8::H)).with(preg(Gpr8::L)).with(preg(Gpr8::A))
+}
...
+Inst::Move8 { dst, src } => emit_ld_r_r(sink, hw_enc(dst.to_reg()), hw_enc(*src)),
```

The ABI assigns one spill slot per integer byte and advertises these registers
to regalloc2. A test checks the `LD A,B` encoding (`0x78`). Without operand
uses/defs and the allocatable set, generated code could not safely participate
in register allocation.

Commit: `43f09482` — Cranelift (`third_party/wasmtime`). Purpose: Make register
allocation usable for generated LR35902 instructions. Change: Exposed the seven
allocatable byte registers and taught the ABI how to represent byte spills and
register moves. Implementation: Mapped B, C, D, E, H, L, and A to physical
registers; added `Move8`, dummy uses, operand collection, and one-byte spill
slots, with allocator tests. Constraint: Pair operations must coordinate
component bytes, so the allocator receives byte registers rather than fictitious
general 16-bit registers.
