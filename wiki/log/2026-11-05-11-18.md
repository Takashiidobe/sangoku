# Cranelift 0ff67e17 — Emit wide stack-address sequences

_2026-11-05 11:18:37_

## Context

Stack locals are reached with `ld hl, sp + n`, whose displacement is a signed
byte. With outgoing arguments and spills, frame offsets can exceed that range
(`-128..=127`), and the instruction cannot encode them. The hardware has no
wider SP-relative mode. Commit `0ff67e17` in Cranelift (`third_party/wasmtime`);
no bead.

## Case

A stack load or store at slot offset 130.

## Before

`LoadStack8`/`StoreStack8` printed a single `ld hl, sp + offset` with the full
offset, which is unrepresentable above 127.

## After

```asm
ld hl, sp + 127
inc hl
inc hl
ld a, [hl]
```

## How

`asm_stack_address` in `inst/mod.rs` clamps the offset to the signed-byte range,
emits `ld hl, sp + base`, then adds `inc hl`/`dec hl` repeats for the rest.
Loads and stores reuse it. Test
`expands_stack_offsets_outside_signed_byte_range` checks that offset 130 starts
with `ld hl, sp + 127`, `inc hl`, `inc hl`.

## Alternatives

A single SP displacement is impossible outside the 8-bit range, so this is a
software sequence rather than a wide SP-relative mode. Cost per extra `inc hl`
is not recorded.
