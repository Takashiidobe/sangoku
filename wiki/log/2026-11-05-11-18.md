# Cranelift 0ff67e17 — Emit wide stack-address sequences

_2026-11-05 11:18:37_

## Files and implementation

`cranelift/codegen/src/isa/lr35902/inst/mod.rs` replaces a single SP-relative
address with an expansion for offsets outside the signed-byte range:

```diff
+let base = offset.clamp(i8::MIN as i32, i8::MAX as i32);
+let mut lines = vec![format!("ld hl, {}", asm_sp_offset(base))];
+if offset > base { lines.extend(repeat_n("inc hl", (offset - base) as usize)); }
+else if offset < base { lines.extend(repeat_n("dec hl", (base - offset) as usize)); }
```

Loads and stores reuse this sequence. A test checks that offset 130 becomes
`ld hl, sp + 127` followed by two `inc hl` operations. The alternative of
encoding one SP displacement is impossible outside the hardware's signed 8-bit
range.

Commit: `0ff67e17` — Cranelift (`third_party/wasmtime`). Purpose: Address stack
locations outside the signed displacement supported by a single LR35902
instruction. Change: Added multi-instruction stack-pointer address generation.
Implementation: The emitter breaks a wide offset into supported adjustments and
constructs the effective address in HL. Tradeoff: This is a software sequence
rather than relying on an unavailable wide SP-relative addressing mode.
