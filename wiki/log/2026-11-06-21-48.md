# Legalize i64 into paired i32 values (sangoku-7qz.9.1)

_2026-11-06 21:48:42_

## Context

Rust `u64`/`i64` appear throughout `core`, but a single CLIF `i64` would need
eight byte registers and the machinst `ValueRegs` limit is four. sangoku-7qz.9.1
(P0) asked for a CLIF-to-CLIF legalization that replaces every `i64` SSA value
with low/high `i32` values before machine lowering, shared by `sangoku lower`
and `cg_clif`, diagnosing unsupported opcodes instead of silently truncating.
Representation is documented in `wiki/concepts/64-bit-integer-legalization.md`.

## Case

```rust
fn add(a: u64, b: u64) -> u64 { a + b }
```

## Before

`i64` was unsupported at every op (coverage matrix).

## After

`i64`/`u64` legalize across arithmetic, memory, control flow, signatures, calls
and returns. All 95 nextest tests pass; `u64` ROMs build at opt levels 0/2 and
the blank-ROM smoke passes.

## How

- Pre- and post-optimization legalization for generated `i32` shifts; lowerings
  for `bmask`, wide `select` conditions, `isplit` and `iconcat`.
- Fixed indirect-call clobbers and its return trampoline in binary and RGBDS
  output.
- Bounded emulator checks at none/speed optimization and Rust-to-CLIF-to-RGBDS
  execution.
- Documented the representation and Unicode table ROM costs. Committed the
  earlier UTF-8 core restoration (sangoku-30k.1) inside the Rust submodule.

## Alternatives

Not done: division/remainder, multiply-high/overflow and `cls` for `i64`,
tracked by sangoku-7qz.9.2.
