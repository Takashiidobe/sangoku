# Restore UTF-8 string behavior in core (sangoku-30k.1)

_2026-11-06 20:46:44_

## Context

The Rust fork carried ASCII-only changes to `core` strings and chars, which
diverge from the stable behavior of `str`, `char` and the parsers for any valid
Unicode scalar. sangoku-30k.1 reverts them (the project now calls them a known
mistake). Unicode lookup tables are fixed read-only data that cost ROM only when
their lookup path is linked, so the cost question moves to deliberate API choice
and measurement, documented in `wiki/concepts/concepts.md` ("Unicode lookup
tables").

## Case

`core` string, character, escape, pattern, Unicode and network parser paths that
had target-specific ASCII-only behavior.

## Before

Those paths behaved differently from other Rust targets on non-ASCII input.

## After

Target-specific ASCII-only behavior is removed. An alloctests regression covers
forward and reverse `chars()`/`char_indices()` across UTF-8 width boundaries.
Host stage 2 alloctests passed. Root nextest: 92 passed.

## How

Edits in the Rust submodule `core`, committed with sangoku-7qz.9.1's work.

## Alternatives

Not done: the full toolchain rebuild reached the Cranelift backend build but
failed with missing Cranelift dependency crates, so target-side MIR/CLIF/
emulator coverage remains blocked. FileCheck failed on the same backend build
error.
