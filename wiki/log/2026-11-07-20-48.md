_2026-11-07 20:48:53_

volatile_store as plain memory ops, so once read_volatile was MIR-inlined,
Cranelift alias analysis forwarded the 0x81 store to 0xFF02 into the serial
poll loop. Scalar volatile accesses now set the Cranelift volatile MemFlag
(rustc_codegen_cranelift intrinsics/mod.rs). Not caused by the spill change;
reverting wasmtime to before 940841a still failed. Closed 30k.9.1.9.4.

rustc_command now passes -Zinline-mir=yes everywhere (core/alloc builds too).

17450 bytes (> 16 KiB bank), so opt 0 uses -Zinline-mir-hint-threshold=50;
threshold 50 at z was worse for every example. Closed 30k.9.1.9.5.
