# Prototype an archived single-file compiler distribution (sangoku-375)

_2026-11-07 18:18:58_

## Context

The compiler needs a pinned Rust fork, a cranelift backend and a pile of target
libraries, so trying it meant building the whole chain from a checkout.
`sangoku-375` (feature, P1) asked for one relocatable `sangoku` executable using
an external RGBDS, with no Cargo/rustup, and a note on whether extraction or
dynamic libraries remain.

## Case

Run `sangoku` outside the checkout with only RGBDS on `PATH`.

## Before

Every command assumed the source checkout, Cargo and rustup.

## After

`build/dist/sangoku` is 215137171 bytes (~205 MiB): a static musl Linux x86-64
launcher with dynamically linked compiler components extracted on first use. An
isolated test hides the checkout, exposes only RGBDS, uses a relative cache path
with spaces, and passes 13 invocations: three executed examples, six
optimization levels, example/MIR/CLIF/lower commands and cache reuse. Full
nextest 139/139; clippy, fmt, LSP, diff and Python syntax checks pass.

## How

`src/bundle.rs`: the launcher detects an appended gzip/tar archive, verifies its
SHA-256 and atomically extracts it into a digest-keyed cache (concurrent
extraction and reuse are tested). `tools/bundle_toolchain.py` packages the
pinned rustc driver, backend, host loader/shared libraries, standalone CLIF
lowerer, target core/builtins for all six optimization levels, runtime assembly,
target/header assets and examples. Bundled builds call extracted tools directly;
artifacts go in the caller's directory. Frontend and CLIF commands now pass
explicit target library metadata. `tools/test_bundle.py` is the bubblewrap smoke
test; docs in `wiki/distribution.md`. No vendored source changes.

## Alternatives

RGBDS stays external. The binary is not fully static: compiler components are
dynamically linked and extracted on first use.
