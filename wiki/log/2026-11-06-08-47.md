# Compare 16-bit multiplication loops (sangoku-xtm)

_2026-11-06 08:47_

## Context

sangoku-xtm (P2) asked to review `runtime/mul16.asm` against a supplied Z80
MSB-first shift-and-add loop for correctness, SM83 porting needs, code size and
instruction timing, recording findings without changing the runtime. A 16x16
multiply helper is called from every `u16` `*` on a CPU with no multiply
instruction, so both bytes and clocks matter. The comparison found a real
defect, tracked as sangoku-9ud. Closed: "Compared assembled implementations,
timing, and ABI; verified 10121 input pairs in a small instruction interpreter".

## Case

The backend passes lhs low/high in `B`/`C` and rhs low/high in `A`/`[SP+2]`. The
current helper interprets both operands with their bytes reversed.

```text
1 * 1  ->  0
```

## Findings

Assembled the current helper and a temporary ABI-adapted port with RGBDS.

```text
                       size    clocks (incl. RET, excl. CALL)
current helper         27 B    1028 + 4p
port, full operand     30 B    848 + 4p
port, rhs < 256        30 B    480 + 4p
```

`p` is the rhs population count. The port returns the low product byte in `A`
and the high byte in `B`. Validated 10,121 boundary and seeded random pairs with
a temporary instruction interpreter, not a full emulator: the port matches
wrapping multiplication; the existing helper matches multiplication of
byte-swapped inputs. Temporary harness: `/tmp/sangoku-compare-mul.py`. Runtime
sources unchanged; `cargo clippy --allow-dirty --fix` and `cargo fmt` passed.
