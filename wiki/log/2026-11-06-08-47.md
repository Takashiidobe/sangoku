# Compare 16-bit multiplication loops

Reviewed runtime/mul16.asm against the supplied Z80 MSB-first shift-and-add loop.
The backend passes lhs low/high in B/C and rhs low/high in A/[SP+2], but the
current helper interprets both operands with their bytes reversed: 1 * 1 gives 0.
Tracked the fix as sangoku-9ud; completed comparison issue sangoku-xtm.

Assembled the current helper and a temporary ABI-adapted port with RGBDS.
Current size is 27 bytes; the port is 30 bytes. Including RET, excluding CALL,
current timing is 1028 + 4p clocks. The port takes 848 + 4p clocks for a full
operand, or 480 + 4p when rhs < 256; p is rhs population count.
The port returns the low product byte in A and the high byte in B.

Validated 10,121 boundary and seeded random pairs using a temporary instruction
interpreter, not a full emulator. The port matches wrapping multiplication;
the existing helper matches multiplication of byte-swapped inputs.
Temporary harness: /tmp/sangoku-compare-mul.py. Runtime sources unchanged.
Quality gates: cargo clippy --allow-dirty --fix and cargo fmt passed.
