# Enable implicit sret for LR35902 wide returns (sangoku-30k.9.1.1)

_2026-11-07 14:04:16_

## Context

Lowering all of `core` to LR35902 failed on 12 functions with
`LR35902 stack return values require enable_multi_ret_implicit_sret`: `u128` and
wide-tuple returns such as `overflowing_mul`, `fmt::num::div_rem_1e16`,
`Binary`/`LowerHex` `fmt`, `dec2flt::lemire::full_multiplication`, bignum
`full_div_rem` and `io::error::Custom::into_raw`. The ABI has only 7 return
registers, so a 16-byte `i128` return needs a return area. Core non-generic
probe went from 3221 to 3233 of 3235 lowering.

## Case

A libcall such as `__rust_u128_mulo` returning `i128` (16 bytes, more than the 7
return registers):

```rust
pub fn mulo(a: u128, b: u128) -> bool {
    mul_with_overflow(a, b).1
}
```

## Cause

`cg_clif` did not enable `enable_multi_ret_implicit_sret` for Z80, even though
the ISA ABI already implements the return-area hooks and the emulator CLIF
fixtures already set the flag.

## Fix

Enable the flag for Z80 in `cg_clif`. Regression: fixture
`tests/fixtures/core/wide-return.rs` with the lowering-only nextest test
`wide_integer_libcall_returns_lower_through_the_backend`; the old backend fails
it with the sret error above.

## Alternatives

Explicit sret in `cg_clif` was the other option in the bead. Not covered:
execution of stack returns is only covered by the existing `abi.clif` emulator
tests, not by a Rust-level run. Remaining core failures: 2 for stack slot
alignment (`sangoku-30k.9.1.2`). New gap: `__rust_u128_mulo` is an undefined
link symbol (new bd child of `sangoku-30k.9.1`). Not pushed.
