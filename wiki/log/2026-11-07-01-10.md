# Stack returns via an implicit return area (sangoku-7qz.7)

_2026-11-07 01:10_

## Context

The ABI passed args in `B`,`C`,`A` then stack and returned in `A`,`B`,`C`,`D`,
`E`,`H`,`L`, but stack return values and indirect return areas were unsupported
("LR35902 stack return values are not supported"). Seven byte registers cannot
hold `i64`/`i128`/`f64` or large aggregates, so sangoku-7qz.7 (P0) asked to
define and document the convention and prove functions with many or wide args
and wide returns round-trip in the emulator.

## Case

A function returning more than fits in the remaining return registers, e.g. four
`i32` returns, or taking five `i32` args.

## Before

```text
LR35902 stack return values are not supported
```

## After

Such functions compile and round-trip across a call in the emulator.

## How

- ABI: a returned value that does not fit the remaining return registers goes
  whole into a caller-allocated return area, reached through a hidden 16-bit
  pointer argument appended after the declared args. Needs
  `enable_multi_ret_implicit_sret`; without it the backend now reports
  Unsupported instead of panicking. Documented in README.
- Shared machinst: the return-area pointer is now `ValueRegs` (was one `Reg`,
  which cannot hold a 16-bit pointer here). New defaulted
  `ABIMachineSpec::gen_ret_area_addr` / `gen_store_ret_area`;
  `gen_retval_area_setup` returns several insts. Other ISAs keep the old
  single-register behaviour. `lr35902` overrides both hooks (`StackAddr16` and
  `StoreMem8` through the pointer).
- Caller side: `CallKnown`/`CallIndirect` never loaded stack-carried results.
  Both the binary emitter and the text printer (`pretty_print_inst`, which feeds
  `lower` output) now load them after the call, including copies into spill
  slots with `AF`/`HL` preserved.
- Test: `fixtures/emulate/abi.clif` + `lowered.rs`
  `many_wide_arguments_and_stack_returns_round_trip` (five `i32` args, one `i32`
  return; four `i32` returns). Coverage matrix regenerated with the sret flag
  on.

## Alternatives

Not done: `i64`/`i128` still fail with "requires 8 registers" (`ValueRegs` max
4); filed as a follow-up under sangoku-7qz.
