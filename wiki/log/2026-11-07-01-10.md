# 7qz.7: stack returns via implicit return area

- ABI: args B,C,A then stack; returns A,B,C,D,E,H,L. A returned value that does not fit in the remaining return registers goes whole into a caller-allocated return area, reached through a hidden 16-bit pointer argument appended after the declared args. Needs `enable_multi_ret_implicit_sret`; without it the backend now reports Unsupported instead of panicking. Documented in README.
- Shared machinst: the return-area pointer is now `ValueRegs` (was one Reg, which cannot hold a 16-bit pointer here). New defaulted `ABIMachineSpec::gen_ret_area_addr` / `gen_store_ret_area`; `gen_retval_area_setup` returns several insts. Other ISAs keep the old single-register behaviour.
- lr35902: overrides both hooks (StackAddr16 and StoreMem8 through the pointer).
- Caller side: CallKnown/CallIndirect never loaded stack-carried results. Both the binary emitter and the text printer (`pretty_print_inst`, which feeds `lower` output) now load them after the call, including copies into spill slots with AF/HL preserved.
- Test: fixtures/emulate/abi.clif + lowered.rs many_wide_arguments_and_stack_returns_round_trip (five i32 args, one i32 return; four i32 returns).
- Not done: i64/i128 still fail with "requires 8 registers" (ValueRegs max 4); filed as a follow-up under 7qz. coverage matrix regenerated with the sret flag on.
