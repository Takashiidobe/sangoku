# Cranelift 4515f1de — Add Z80 ABI and machine-instruction structure

_2026-11-05 08:35:52_

## Context

A Cranelift backend needs an ABI, register and instruction definitions, an
emitter and ISLE lowering wiring before it can compile anything. Commit
`4515f1de` (Cranelift fork, `third_party/wasmtime`) lays all of that out as a
scaffold (about 1100 lines added), so later commits could fill it in. No bead id
is recorded.

## Case

The registered Z80 ISA (`a48d255a`, `6d3854dd`) had no machine-instruction type,
register classes or calling convention, so there was nothing to lower into.

## Before

Only the `TargetIsa` skeleton in `isa/z80/mod.rs`.

## After

New files `isa/z80/abi.rs`, `inst/` (`mod.rs`, `emit.rs`, `emit_state.rs`,
`regs.rs`), `sdcc.rs`, `inst.isle`, `lower.isle`, `lower.rs`, `lower/isle.rs`,
and `meta/src/isle.rs` registers generated lowering rules. The ABI starts with
an 8-bit word and leaves argument allocation incomplete:

```diff
+fn word_bits() -> u32 { 8 }
```

## How

Defined register classes, machine instruction/emitter scaffolding, ABI hooks and
generated ISLE input. `sdcc.rs` records candidate Z80/SM83 calling conventions,
but the lowerer and emitter are still scaffolding. Argument locations and most
target operations were incomplete.

## Alternatives

The scaffold describes several Z80/SM83 conventions, but does not establish the
Rust ABI that `core` needs. It did not implement rustc's eventual C or Rust ABI;
it supplied a structure to port later.
