# Fuse compare and branch (sangoku-i70)

_2026-11-09 16:00:00_

## Context

Byte compares feeding a branch built a 0/1 boolean from a raw `db` run and then
re-tested it, which pinned `A`, `B` and `L` and forced stack spills. sangoku-i70
adds `CompareBranch8`, which branches on the flags from `cp`. Harness total 942
-> 868 bytes (2.21x -> 2.04x of SDCC): `max_u8` 69 -> 40, `count_eq` 77 -> 45,
`sat_chain` 143 -> 130.

## Case

`if x > m { m = x }` in `max_u8`: an unsigned byte compare feeding a branch.

## Currently emits

```asm
db $79, $BD, $38, $08, $28, $06, $18, $00, $2E, $01, $18, $02
db $2E, $00
ld b, c
ld a, l
or a
jp nz, .block6
```

## Should emit

```asm
ld a, h
cp c
jp z, .block5
jp nc, .block6
```

This is the actual output after the change. The remaining gap is that both jumps
land on a block that only does `jp` (sangoku-2ea).

## How

`Brif(Icmp(i8, eq/ne/unsigned))` with a unique-use `icmp` was `Compare8`
followed by `BranchIf`; it is now one `CompareBranch8` (`inst.isle`,
`inst/emit.rs`, `inst/mod.rs`, `fuse_compare_branch` in `lower.rs`). It emits
`ld a, lhs`, `cp rhs`, then `jp cc, taken` and `jp not_taken`; `>` and `<=` add
one `jp z` or `jp c`. Only `A` is clobbered, and the `icmp` is never lowered
because its result has no other use. Signed, 16-bit and 32-bit compares keep the
boolean path. `tests/core_rom/compare_branches.rs` checks all six unsigned
conditions at opt `0`, `2` and `z`; default `cargo nextest` passed 211 tests.

## Alternatives

- Fuse signed compares too: needs `xor $80` on both operands and a scratch
  register, so deferred.
- Keep the boolean and peephole `ld a, r` / `or a` after it: still pins
  registers for the 0/1 value, so it does not fix the pressure.
- Emit `jr` instead of `jp`: smaller, but needs branch relaxation (sangoku-2ea).
