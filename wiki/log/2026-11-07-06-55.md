# Basic four-limb f128 legalization (sangoku-7qz.9.5)

_2026-11-07 06:55:58_

## Context

`sangoku-7qz.9.5` (P0): binary128 is 16 bytes, so like f64 it cannot live in
LR35902 registers. Basic support means moving and sign-editing the 128 bits
without losing any of them; f32/f64 arithmetic is not a substitute. Arithmetic,
comparisons, rounding and conversions stay in `sangoku-7qz.9.6`.

## Case

f128 constants, bitcasts, memory, select, block arguments, direct calls/returns
and `fneg`/`fabs`/`fcopysign`. Fixture `tests/fixtures/emulate/split-f128.clif`;
Rust example `examples/f128.rs` (constant and memory).

## Before

f128 was excluded by cg_clif's blanket LR35902 float exclusion and had no split
legalization (not recorded: exact error text).

## After

Bounded none/speed emulator fixtures preserve IEEE patterns, big-endian memory
and calls. Rust f128 constant/memory example and emulator regression pass; f128
and blank Rust-to-ROM builds pass. Separate operation ROMs avoid ROM0 overflow.

## How

- f128 as four i32 bit-pattern limbs, sign bit in the highest limb.
- Constant-pool bytes decoded without reducing binary128 precision.
- Shared highest-limb sign handling with f64; reused i128 memory, select, flow
  and call splitting.
- Allowed f128 through the old cg_clif LR35902 float exclusion.
- Updated operation coverage and legalization concepts; README stays focused on
  usage. Rebuilt cg_clif. All 100 nextest tests pass; clippy, fmt, LSP and diff
  checks pass.
- Backend commits: `ee4c3b7b` (wasmtime), `59b029d` (cg_clif).

## Alternatives

Not done: arithmetic, comparisons, rounding and conversions remain in
`sangoku-7qz.9.6`.
