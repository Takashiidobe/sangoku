# Bounded wider and widening multiplication (sangoku-mt4.7, .1, .2)

_2026-11-08 16:10_

## Context

`sangoku-mt4.7` (epic) asked to implement and wire wider/widening multiplication
into Cranelift: native signed/unsigned `16x16->32` helpers with size/speed
kernels, used for 16-bit high-half and overflow and for matching `i32` products
and partial products, while preserving general low-32 wrapping and existing

> 32-bit algorithms. The user explicitly requested a bounded implementation with
> a few representative checks, not an extensive audit. Existing low-32 wrapping
> kernels and 8-bit high/overflow behavior are kept.

## Case

Sign/zero-extended `i16` multiplication into `i32`, 16-bit high-half/overflow,
and the partial products of 32-bit high/overflow.

## Currently emits

Generic `i32` multiplication (`mul32`); the listing is not recorded. Mixed
extensions still fall back to it.

## Should emit

```text
shape               size/speed linked bytes  size/speed T-cycles, 0xffff x 0xffff
unsigned 16x16->32  32/252                   1292/1072
signed 16x16->32    93/313                   1688/1468
```

ABI: `lhs` `B`/`C`, `rhs` `A`/`[SP+2]`, full product `A`/`B`/`C`/`D`
low-byte-first. Unsigned needs no local stack; signed uses six frame bytes plus
a nested two-byte return. Both preserve SP and incoming arguments; all public
registers/flags may be clobbered. Cycles cover entry through `RET`, excluding
outer caller costs. No tables or scratch RAM.

## How

The unsigned kernel maintains multiplicand `DE` and product `HL`/`BC`,
conditionally adds then shifts through carry for 16 steps. Compact loops; speed
unrolls all steps and short-circuits either zero operand (unsigned 0 x max takes
100 cycles). A 61-byte signed wrapper shares that kernel and corrects the high
half by subtracting `rhs` when `lhs` is negative and `lhs` when `rhs` is
negative, which handles MIN and -1 without negating either input.

Added `GbcUmul16Wide`/`GbcSmul16Wide` typed signatures and both symbol mappings.
Cranelift uses them for 16-bit high-half/overflow and matching
sign/zero-extended `i16` multiplication into `i32`; known masked low limbs or
logical shifts exposing at most 16 bits can use unsigned widening. Mixed
extensions safely fall back to generic `i32`. The existing 32-bit high/overflow
decomposition selects the new kernels for its partial products. No >32-bit
helper is added.

Tests: nine direct pairs (zeros in either position, 1x1, max x max, signed MIN x
-1, MIN x MIN, signed MAX x 2, asymmetric/carry patterns). Tiny `no_core` Rust
at `0`/`z` checks full signed/unsigned/mixed products, live inputs and overflow.
CLIF checks six representative pairs at 8/16/32 for signed/unsigned high halves
and overflow value/flag pairs, plus full16 products; explicit call checks prove
the new paths are selected; stack arguments and non-stack writes are checked. 19
targeted multiplication/linkage tests pass in 1.16 seconds; the final three
widening tests pass in 0.22 seconds after adding the speed zero shortcut. All 36
LR35902 backend tests pass; release backend and standalone CLIF tool rebuilt.
`cargo clippy --allow-dirty --fix`, fmt, LSP diagnostics and diff checks pass.
Reproduce: `cargo nextest run --no-fail-fast -E 'binary(widen_multiply)'`.

## Alternatives

No core, Rust fork or application ROM rebuild, and no broad SDCC/exhaustive
audit.
