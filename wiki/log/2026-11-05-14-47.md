# Cranelift e9a49131 — Support multi-register return pointers

_2026-11-05 14:47:28_

## Context

Returning large values from functions uses a structure-return (`sret`) pointer.
Generic Cranelift lowering asserted that this pointer occupies exactly one
register. On `lr35902` a 16-bit pointer is two byte registers, so the assertion
blocked multi-register target values. Commit `e9a49131` in Cranelift
(`third_party/wasmtime`).

## Case

A function with an `sret` parameter whose pointer is split across two byte
registers.

## Before

`assert!(regs.len() == 1);` in `machinst/lower.rs` fires.

## After

The pointer is kept as `ValueRegs`, so split-pointer values flow through generic
lowering:

```rust
let sret_reg = sret_param.map(|param| value_regs[param]);
```

## How

`cranelift/codegen/src/machinst/lower.rs` drops the assertion, with a one-line
adjustment in `vcode.rs`. The shared abstraction is fixed rather than
special-casing LR35902, so other split-register targets can use the same path.

## Alternatives

Not done: actual stack-return-value support is still incomplete in the target
ABI. Tests: not recorded.
