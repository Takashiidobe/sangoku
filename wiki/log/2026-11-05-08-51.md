# rustc_codegen_cranelift d03fa6e — Track the Cranelift fork branch

_2026-11-05 08:51:06_

## Context

The previous commit (`3a8531a`) pointed the backend at sibling path checkouts,
which only works with one particular directory layout. Commit `d03fa6e` makes
dependency resolution follow the shared LR35902 Cranelift fork instead. No bead
id is recorded.

## Case

A fresh clone without the sibling `../wasmtime` layout could not resolve the
Cranelift crates.

## Before

```text
cranelift-codegen = { path = "../wasmtime/cranelift/codegen", ... }
```

## After

```diff
-cranelift-codegen = { path = "../wasmtime/cranelift/codegen", ... }
+cranelift-codegen = { git = "https://github.com/Takashiidobe/wasmtime.git",
+    branch = "gbc-lr35902", ... }
```

## How

Switched all Cranelift crates (codegen, frontend, module, native, JIT, object)
from paths to the fork's `gbc-lr35902` branch in `Cargo.toml` and refreshed
`Cargo.lock`, which records the resolved commit. Keeping every crate on one
branch avoids mixing API revisions. The repository is named `wasmtime`, but this
is the project's Cranelift fork.

## Alternatives

Local paths were the other option; they require a specific sibling checkout
layout. A branch dependency makes the fork explicit and reproducible in
`Cargo.lock`.
