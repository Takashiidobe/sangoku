# Linking real core into a ROM

_2026-11-07 16:30:00_

sangoku-30k.9.1.8: the backend now emits one RGBDS section per function (named after the symbol) instead of one section per codegen unit, so rgblink-level and script-level pruning can work; the cgu header and rgbds::new_source are gone and the lower fixtures were regenerated. tools/link_core.py compiles core, compiler_builtins and a program to assembly, splits the text into sections, keeps those reachable from __rust_gbc_main by following any symbol token that another section defines, and assembles the result. For tests/core_rom/rom.rs (iterator filter/sum/max over a byte array) 104 of 12,255 sections survive, 16,136 bytes. That exceeds the 16 KiB of ROM0 after header and runtime, so a probe link puts everything in ROMX, reads section sizes from the map, fills the ROM0 free space first and moves the rest to ROMX bank 1; a no-MBC 32 KiB cartridge maps both banks at once so ordinary calls work, and rgblink -t rejects anything larger. tests/core_link.rs links and runs the ROM in the emulator and checks gbc_main returns 28. The emulator already handled everything core emitted. Also found: the panic symbol core references is the v0-mangled std-internal name __rust__RNvCsbOwsw4zHH1Z_7___rustc17rust_begin_unwind, so the earlier runtime/panic.asm label (plain rust_begin_unwind) would never have resolved; fixed and the test follows.
