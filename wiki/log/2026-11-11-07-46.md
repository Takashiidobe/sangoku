# sangoku-61a.1 rustc driver: link LR35902 Cranelift without a backend dylib

_2026-11-11 07:46:08_

- bead: sangoku-61a.1
- kind: feature
- area: rustc_codegen_cranelift
- area: distribution
- area: Cargo

Outcome: sangoku compiles ROMs through a pinned rustc driver with the LR35902
Cranelift backend linked into the executable instead of loaded as a plugin.

## Gap and why it mattered

The compiler previously needed an explicit backend shared-library path. Cargo
integration needs a compiler that selects LR35902 for the target while retaining
normal host compilation for build scripts and procedural macros. This change
establishes that compiler entry point without changing the Rust fork.

## Implementation

The backend is now a reusable Rust library with a small compatibility dylib. The
new driver supplies the backend through rustc's existing factory callback. The
CLI, library cache invalidation, rebuild script, and bundle use that driver.

The callback selects Cranelift for the existing z80 target architecture. Host
compilations and explicit backend overrides retain rustc's normal selection. The
rebuild script installs the driver alongside the pinned toolchain's rustc. The
bundle packages it as its compiler and omits the compatibility plugin.

## Before and after

The regression fixture supplies language items and exports this function:

```rust
#[unsafe(no_mangle)]
pub fn answer() -> u8 {
    42
}
```

Before: an initial combined rlib/dylib build still selected the backend dylib;
the driver failed to start without librustc_codegen_cranelift.so. After: a
copied driver emits RGBDS assembly for the same fixture without that dependency
or a backend command-line flag. Its ELF dependencies confirm this.

## Regression and validation

The new bounded test checks target probing and direct assembly emission. It also
runs Cargo checking outside the checkout with a host build script and host
procedural macro. The copied driver runs without LD_LIBRARY_PATH. All 213
default tests and all seven backend unit tests passed. Thirty-seven targeted
warm-cache checks passed, each below ten seconds; the initial run included
shared library-build waits. The hello ROM smoke build, clippy, formatting, and
script syntax checks passed. A bundle with optimization levels 0 and z passed
nine isolated invocations, with the checkout hidden and only RGBDS on PATH,
including emulator execution.

Limits: librustc_driver and its dependencies remain dynamically linked and are
included in the bundle. Target libraries and host macros remain packaged assets.
Cargo target checking works for the fixture; Cargo cannot yet link a ROM. The
target still disables executables, and normal no_std projects need matching
target core metadata. Cargo artifacts and final ROM linking are follow-up work.

See: sangoku-61a for the Cargo workflow and sangoku-61a.2 for artifacts and
linking.
