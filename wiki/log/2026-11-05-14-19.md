# Cranelift 413349fc — Diagnose unsupported value widths

_2026-11-05 14:19:49_

## Files and implementation

`cranelift/codegen/src/machinst/vcode.rs` replaces a panic for values wider than
two registers with a target error:

```diff
-panic!("Value must reside in 1 or 2 registers");
+return Err(CodegenError::Unsupported(format!(
+    "value type {ty} requires {} registers; this backend supports at most 2",
+    regclasses.len()
+)));
```

The failure now identifies the source value width during core compilation. At
this point the backend still did not represent I32; the following commit raises
the shared value container to four parts.

Commit: `413349fc` — Cranelift (`third_party/wasmtime`). Purpose: Turn
unsupported wide values into a useful codegen failure instead of an opaque panic
or malformed output. Change: Added explicit validation/reporting for LR35902
value widths. Implementation: Check the number of machine registers used by a
value during VCode construction and return the backend's unsupported-width
error. Result: This makes `i64` blockers visible while core support is being
expanded.
