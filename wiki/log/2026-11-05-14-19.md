# Cranelift 413349fc — Diagnose unsupported value widths

_2026-11-05 14:19:49_

## Context

Compiling `core` produced values wider than the backend's two-register limit,
and VCode construction answered with an opaque
`panic!("Value must reside in 1 or 2 registers")`. With `core` as the milestone,
each failed attempt needs to say which type blocked it. Commit `413349fc` in
Cranelift (`third_party/wasmtime`).

## Case

Any value whose type needs more than two byte-sized registers on `lr35902`, for
example `i32` or `i64`.

## Before

```text
panic: Value must reside in 1 or 2 registers
```

## After

```text
value type {ty} requires {n} registers; this backend supports at most 2
```

(Format from the diff; type and count filled in.) The error is returned as
`CodegenError::Unsupported`.

## How

`cranelift/codegen/src/machinst/vcode.rs` now checks the register count during
VCode construction and returns `CodegenError::Unsupported(format!(...))` instead
of panicking. This makes `i64` blockers visible while core support is expanded.
At this commit the backend still did not represent `i32`; the next commit raises
the shared container to four parts.
