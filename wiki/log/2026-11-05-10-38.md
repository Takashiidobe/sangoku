# Cranelift f0beaeac — Declare that LR35902 has no unwind data

_2026-11-05 10:38:47_

## Context

Cranelift asks every `TargetIsa` for unwind info after compiling a function. The
LR35902 backend answered with
`unimplemented!("LR35902 does not support unwinding")`, so asking for it crashed
the compiler during code emission. A Game Boy has no unwinder and 32 KB of ROM
leaves no room for one, so the right answer is "none", not a panic. Commit
`f0beaeac` in Cranelift (`third_party/wasmtime`); no bead.

## Case

Any function compiled for `z80-unknown-none` that reaches the unwind-info hook.

## Before

```rust
unimplemented!("LR35902 does not support unwinding");
```

The compiler panicked.

## After

```rust
Ok(None)
```

`cranelift/codegen/src/isa/lr35902/mod.rs` reports no unwind information, which
is the target's honest capability.

## How

One-line change in the `TargetIsa` unwind hook; it reports absence rather than
generating host-style system unwind data. It does not implement Rust panic
recovery.

## Alternatives

Panics and unwinding need a separate runtime policy; the runtime must use
abort/trap behavior unless an unwinder is added later.
