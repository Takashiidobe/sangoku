# Cranelift bd158544 — Add register-only LR35902 ABI

_2026-11-05 09:18:06_

## Files and implementation

`cranelift/codegen/src/isa/lr35902/abi.rs` defines separate register orders for
arguments and returns. The initial ABI rejects indirect return areas, struct
arguments, and values that exceed seven byte-register parts:

```diff
+Args => [B, C, D, E, H, L, A],
+Rets => [A, B, C, D, E, H, L],
...
+return Err(CodegenError::Unsupported(
+    "LR35902 register-only ABI supports up to seven byte parts".into(),
+));
```

`gen_args`/`gen_rets` create explicit machine instructions, and frame prologue
and epilogue are empty for this register-only subset. Tests lock down register
order. Stack arguments were deferred and implemented in a later commit.

Commit: `bd158544` — Cranelift (`third_party/wasmtime`). Purpose: Establish a
callable ABI path for the first small functions. Change: Added argument/return
register placement and call-related instruction support for values that fit
registers. Implementation: The ABI maps eligible parameters and returns to
hardware registers and models call uses/defs; unsupported stack return cases
remain rejected. Tradeoff: This deliberately starts with register-only calls;
stack arguments are added in a later commit rather than mixing an incomplete
stack ABI into the first implementation.
