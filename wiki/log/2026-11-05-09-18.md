# Cranelift bd158544 — Add register-only LR35902 ABI

_2026-11-05 09:18:06_

## Context

Functions need a calling convention before they can be compiled and called.
Commit `bd158544` (Cranelift fork, `third_party/wasmtime`) establishes a
callable ABI path for the first small functions. No bead id is recorded.

## Case

Parameters and returns had no register placement; `abi.rs` left argument
allocation incomplete.

## Before

Argument locations unassigned; no call-related instruction support.

## After

Separate register orders for arguments and returns:

```rust
Args => [B, C, D, E, H, L, A],
Rets => [A, B, C, D, E, H, L],
...
return Err(CodegenError::Unsupported(
    "LR35902 register-only ABI supports up to seven byte parts".into(),
));
```

## How

`isa/lr35902/abi.rs` maps eligible parameters and returns to hardware registers
and models call uses/defs; `gen_args`/`gen_rets` create explicit machine
instructions, and frame prologue and epilogue are empty for this register-only
subset. Indirect return areas, struct arguments, stack return cases and values
exceeding seven byte-register parts are rejected. Tests lock down register
order.

## Alternatives

Stack arguments were deferred and implemented in a later commit rather than
mixing an incomplete stack ABI into the first implementation.
