# Cranelift ede96e8a — Lower traps through RST 10h

_2026-11-05 15:22:42_

## Context

Panics, overflow checks and unreachable paths in `core` all lower to Cranelift
traps. The `lr35902` backend had no encoding for one, and host trap opcodes are
not valid Game Boy code. Commit `ede96e8a` in Cranelift
(`third_party/wasmtime`).

## Case

Any CLIF `trap` instruction.

## Before

No valid target lowering; a host trap opcode or placeholder `unreachable` would
not be LR35902 code.

## After

```asm
rst $10
```

(opcode `0xD7`). The ROM owns the vector at `$10`; current startup code disables
interrupts and loops there.

## How

New `Inst::Trap` machine instruction: `inst/emit.rs` emits `sink.put1(0xD7)`,
`inst/mod.rs` prints `rst $10`, and `lower.rs` maps Cranelift traps to it.

## Alternatives

A host trap opcode or unreachable placeholder was rejected as invalid Game Boy
code; the dedicated vector gives a stable target hook. Tests: not recorded.
