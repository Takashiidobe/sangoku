# Link arithmetic runtime objects only when referenced (sangoku-30k.9.1.9.6)

_2026-11-08 07:49:05_

## Context

An empty `gbc_main` ROM retained the 1066-byte "32-bit runtime" section while
real startup plus header is about 220 bytes. sangoku-30k.9.1.9.6 (P2) selects
runtime sections by reference like other runtime objects. Result: retained
section bytes of `benchmarks/empty.rs` 1286 -> 95 (RGBDS `probe.map` totals).

## Case

Any program that does not use `u32` division, multiplication or wide ops, e.g.
`benchmarks/empty.rs`.

## Currently emits

The selector always added `udiv16`, `mul16` and `wide32`: 1286 retained bytes.

## Should emit

Only objects whose exports are referenced: 95 retained bytes (removed 1066 of
`wide32`, 95 of `udiv16`, 30 of `mul16`). The RGBFIX-padded ROM stays 32768
bytes.

## How

The selector matches unresolved identifiers against exports in the runtime
sources; program-defined helpers do not select duplicate runtime objects.
RGBLINK has no section garbage-collection option, so this uses `sangoku` object
selection.

Tests: empty-ROM map regression; volatile-input `u32` division/remainder ROM on
three deterministic input pairs; the selector regression covers all exported
runtime entries. Deleted the dangling `core_sort_unstable_links_and_runs` test
at the user's request (its fixture was already removed because of retained
sorting machinery). All 152 default-profile nextest tests pass in 8.568s, none
over 10s; the 11 CLI/link unit tests and both new integration tests pass. Hello
smoke build links. Clippy, fmt, LSP and diff checks pass.

## Alternatives

Section garbage collection in RGBLINK is unavailable, so not used. No
`third_party` source changes, no push.
