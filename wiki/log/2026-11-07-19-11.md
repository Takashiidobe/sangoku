# Survey alloc compilation and lowering (sangoku-30k.9.2)

_2026-11-07 19:11:22_

## Context

`sangoku-30k.9.2` (task, P1) asked for the same CLIF-generation report for
`alloc` as for `core`, to learn whether `Vec`, `String`, `Box` and `Rc` can
lower for LR35902 before any heap ROM is attempted. Execution was out of scope
until core was done.

## Case

`tools/core_report.py --alloc` plus a bounded collection driver covering `Vec`,
`String`, `Box`, `Rc` and standard collections.

## Before

No report for `alloc`; its lowering status was unknown.

## After

On the pinned toolchain: alloc 1137/1137 and alloc driver 1238/1238 functions
lower with no backend errors. Core 3184/3184, `compiler_builtins` 2043/2043 and
core driver 921/921 also lower. No alloc compilation blockers within this
coverage.

## How

Counts and coverage limits recorded in the README; a nextest regression
(`alloc_report`) added. Artifacts in `build/alloc-report.json` and
`build/alloc-report/`. No vendored changes. `alloc_report` and `core_report`
tests, clippy, fmt and `git diff --check` pass. Closed `sangoku-30k.9.2`; its
core dependency remains open.

## Alternatives

Not done: allocator hooks (`__rust_alloc_zeroed`, `__rust_dealloc`,
`__rust_realloc` are imported but no global allocator or heap exists) and the
WRAM heap policy, tracked as `sangoku-30k.9.3`. Existing long CLIF filename
warnings remain `sangoku-30k.9.1.11`. Coverage is representative generic code
only.
