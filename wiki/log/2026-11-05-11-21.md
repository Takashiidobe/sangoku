# rustc_codegen_cranelift c60fe1b — Resolve call symbols in RGBDS output

_2026-11-05 11:21:25_

## Context

Cranelift's printed assembly refers to callees as `User(userextname0)`, a debug
name, not a symbol. With more than one codegen unit, calls between separately
emitted functions have to link through `rgblink`, so the references need real
symbol names. Commit `c60fe1b` in `rustc_codegen_cranelift`; no bead.

## Case

Two codegen units where function `one` calls `function_two`.

## Before

```text
call User(userextname0)
```

Not a declared linker symbol, so it cannot link.

## After

```text
call __rust_function_two
```

## How

`src/base.rs` reads `context.func.params.user_named_funcs()`, looks up each
function declaration in the module and takes its `linkage_name`.
`append_function` in `src/rgbds.rs` takes a map `User(ref) -> symbol` and
replaces each reference while printing the function. `symbol_name` encodes
punctuation as `_HH` bytes so identifiers meet RGBDS syntax. A two-codegen-unit
test checks `call __rust_function_two` appears and that `rgblink` resolves it.

## Alternatives

Leaving `User(...)` in the output is not linkable; rewriting from module
declarations preserves the actual linkage name.
