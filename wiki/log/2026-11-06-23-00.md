# Sign extension (sangoku-7qz.3)

_2026-11-06 23:00_

## Context

`sextend` (and `sload8`/`sload16`, split from sangoku-7qz.21) was unsupported.
Every signed widening in Rust (`i8 as i16`, `i16 as i32`) needs it, and the
LR35902 has no sign-extend instruction. sangoku-7qz.3 (P0) required all
extend/reduce pairs to lower and match host results at boundary values.

## Case

`sextend` `i8`->`i16`/`i32` and `i16`->`i32`, plus `sload8`/`sload16`.

## Before

Unsupported in the matrix. Exact diagnostic: not recorded.

## After

```asm
ld a, src
add a, a      ; carry = bit 7
sbc a, a      ; a = 0xFF if bit 7 was set, else 0
ld dst, a
```

New `SignFill8` inst emits this (clobbers `A`). Matrix: `sextend` and `sload*`
ok for `i8`/`i16`/`i32`.

## How

`sextend` copies the source bytes, sign-fills the first extra byte and copies it
into any remaining ones. `sload8`/`sload16` reuse the load arm with the same
fill. Test: `tests/lowered.rs` `sign_extension_matches_host` (boundary values,
including `sload` at offset 300). Note the first `i8` arg is in `B`.

## Alternatives

Not done: `i64`/`i128` stay with sangoku-7qz.9.
