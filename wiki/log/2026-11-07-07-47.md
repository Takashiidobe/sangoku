# Lower missing i128 operations with byte arrays (sangoku-7qz.9.3)

_2026-11-07 07:47:59_

## Context

`sangoku-7qz.9.3` (P0): i128 division/remainder, multiply-high and `cls` were
the last unsupported native integer ops. The obvious lowering, expanding the
four-i32-limb value in SSA, keeps the whole 128-bit state live in registers and
the LR35902 has almost none to spare: the first attempt measured signed division
at 16036 bytes and signed multiply-high at 19564 bytes, in a 32 KB ROM. That
attempt was discarded. Result: standalone functions of 4-6 KB, an 8192-byte
per-function guard, and a complete native integer matrix.

## Case

```text
v3 = udiv v1, v2     ; i128; also sdiv, urem, srem, umulhi, smulhi, cls
```

Fixture: `tests/fixtures/emulate/split-i128-arithmetic.clif`.

## Currently emits

Register-heavy limb expansion: signed division 16036 bytes, signed multiply-high
19564 bytes.

## Should emit

Byte loops over stack-memory arrays; four-i32 values stay only at operation and
ABI boundaries, loop state stays in memory. Real standalone sizes (bytes,
excludes linked runtime):

| operation | none | speed |
| --------- | ---: | ----: |
| udiv128   | 5041 |  4882 |
| sdiv128   | 6054 |  5957 |
| urem128   | 4847 |  4829 |
| srem128   | 5910 |  5826 |
| umulhi128 | 4264 |  4286 |
| smulhi128 | 5052 |  5352 |

## How

128-step outer loops with byte-wise inner loops for shifts, carry/borrow
propagation and sign correction; division reuses the subtraction borrow to keep
or restore the remainder; sign counts scan sixteen normalized bytes. Bounded
emulator fixtures cover host-reference results, signed boundaries and divide
traps. Added an 8192-byte per-function size guard; generated native integer
coverage is now complete. All 103 nextest tests pass; rebuilt cg_clif and linked
the blank ROM. Clippy, fmt, LSP and diff checks pass. Updated concept docs and
formatted generated Markdown.

## Alternatives

These remain costly inline bodies; `sangoku-7qz.9.8` tracks shared and smaller
runtime helpers. Checked i128 multiplication remains compiler-builtins work
under `sangoku-57q.5`. The discarded register-heavy attempt is described above.
