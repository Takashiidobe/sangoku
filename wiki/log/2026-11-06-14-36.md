# Audit SM83 population count

Completed sangoku-mt4.3 and its correctness/measurement children. Replace
popcnt.i16: YES, with native table-free parallel counting. The runnable
prototype is 51 code bytes and 216 T-cycles including RET, preserving HL with no
table or owned scratch RAM. Production replacement is separate task sangoku-pg3.

The actual pinned compiler probe emits 207 bytes and miscompiles: input zero
returns 11 or 12 depending on the stack address. Allocation-generated spill and
reload edits overwrite live HL while computing stack addresses. General repair
is tracked in sangoku-7em; production compiler sources are unchanged here. An
audit-only push/pop repair is correct at 211 bytes and 936 cycles.

Compared eleven correct implementations with body, complete caller, live-input
caller and eligible inline modes. The smallest loop is 13 bytes/664 cycles;
page-aligned nibble lookup is 34 code + 16 table bytes/164 cycles; byte lookup
is 10 code + 256 table bytes/60 cycles. Alignment gaps and caller saves are
separate costs. Mandatory tables and unconditional outlining: NO. Parallel
counting is the default recommendation; actual backend allocation costs remain
to measure.

Built ~/sdcc out of tree with only SM83 enabled. Its width-specialized generic
count-ones C loop compiles to 42 adapted bytes/5232 cycles. No dedicated
Z80/SM83 population-count routine was found. Frozen Rust/SDCC output, source
hashes, versions and build commands are in
tests/fixtures/popcount/provenance.json.

Reproduction and full tradeoffs: [audit](../audits/popcount16.md), with linked
assembly fixtures, baseline generator and per-class CSV. Retained objects, ROMs,
maps, symbols, hashes and detailed JSON are in build/popcount-audit.

Validation: python -B tests/audit_popcount.py --samples 1024 --seed 0
--exhaustive16 --output build/popcount-audit/results.json --artifacts
build/popcount-audit/artifacts --csv wiki/audits/popcount16.csv

All 342928 accepted executions pass, including the complete u16 domain for
parallel counting and all three lookup variants. The frozen broken output is
isolated from accepted timings. Actual regenerated compiler output matches its
frozen image; fixture formatting changes were checked for ROM byte equivalence.

python -B -m unittest discover -s tests passes all 50 tests, including poisoned
scratch state, alternate stacks, live inputs and independent exhaustive SWAP
flags/timing tests. Ruff check/format, cargo test --bins, cargo clippy
--allow-dirty --fix, cargo fmt and git diff --check pass. No vendored sources
were changed, and svn status on the SDCC checkout remains clean.
