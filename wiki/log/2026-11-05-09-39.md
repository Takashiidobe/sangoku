# Cranelift 8f6da746 — Add byte subtraction and bitwise operations

_2026-11-05 09:39:52_

## Context

Addition alone cannot express compiler-generated byte code. Commit `8f6da746`
(Cranelift fork, `third_party/wasmtime`) adds `isub`, `band`, `bor` and `bxor`
for I8. No bead id is recorded.

## Case

Test `compiles_i8_sub_and_bitwise_ops_to_lr35902_machine_code`: `0x5A - 0x0F`,
then `and`, `or` and `xor` chained, then return.

## Before

Only I8 constants, return and add lowered.

## After

New accumulator-form instructions; the LR35902 does these ALU operations only
through `A`:

```rust
Inst::Sub8 { dst, lhs, rhs } => emit_accumulator_op(sink, 0x90, dst, lhs, rhs),
Inst::And8 { dst, lhs, rhs } => emit_accumulator_op(sink, 0xA0, dst, lhs, rhs),
Inst::Xor8 { dst, lhs, rhs } => emit_accumulator_op(sink, 0xA8, dst, lhs, rhs),
Inst::Or8  { dst, lhs, rhs } => emit_accumulator_op(sink, 0xB0, dst, lhs, rhs),
```

## How

`isa/lr35902/lower.rs` maps the four opcodes to the new machine instructions;
`inst/emit.rs` copies the left operand to `A` when necessary, applies the
operation, then copies `A` to the result register, and models `A` as a clobber
so the allocator knows about the temporary accumulator use. The test asserts the
final byte is `0xC9`.

## Alternatives

None recorded. Reusing accumulator instructions matches LR35902 hardware.
