# Cranelift 95b2d6d7 — Allow four-register values

_2026-11-05 14:27:12_

## Files and implementation

`cranelift/codegen/src/machinst/valueregs.rs` expands `ValueRegs` from two parts
to four; `vcode.rs` maps four register classes into that representation:

```diff
-const VALUE_REGS_PARTS: usize = 2;
+const VALUE_REGS_PARTS: usize = 4;
...
+ValueRegs::four(check(VReg::new(v, rc0))?,
+    check(VReg::new(v + 1, rc1))?,
+    check(VReg::new(v + 2, rc2))?,
+    check(VReg::new(v + 3, rc3))?)
```

The LR35902 backend maps I32 to four I8 registers. The limit is explicitly four;
I64 still requires eight and remains unsupported. This shared Cranelift change
avoids adding an LR35902-only value container.

Commit: `95b2d6d7` — Cranelift (`third_party/wasmtime`). Purpose: Enable
bytewise `i32` values required by integer and memory routines in `core`. Change:
Extend Cranelift's value-register representation to hold four physical byte
registers and permit four-byte values. Implementation: Updated `ValueRegs`
handling and VCode validation; the LR35902 type mapping supplies one I8 register
per byte. Limit: This raises support to 32 bits; it does not add eight-register
`i64` values.
