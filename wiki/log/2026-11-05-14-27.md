# Cranelift 95b2d6d7 — Allow four-register values

_2026-11-05 14:27:12_

## Context

The LR35902 has 8-bit registers, so an `i32` is four of them. Cranelift's
`ValueRegs` held at most two parts, which made `i32` unrepresentable even though
integer and memory routines in `core` need it. Commit `95b2d6d7` in Cranelift
(`third_party/wasmtime`).

## Case

Any `i32` value (four bytes) in `core`.

## Before

`i32` hit the previous commit's "supports at most 2" diagnostic.

## After

`i32` maps to four `I8` registers, one per byte.

## How

`cranelift/codegen/src/machinst/valueregs.rs` expands `ValueRegs` from two parts
to four, and `vcode.rs` maps four register classes into it:

```rust
const VALUE_REGS_PARTS: usize = 4;
ValueRegs::four(check(VReg::new(v, rc0))?,
    check(VReg::new(v + 1, rc1))?,
    check(VReg::new(v + 2, rc2))?,
    check(VReg::new(v + 3, rc3))?)
```

Changing the shared Cranelift container avoids adding an LR35902-only value
type.

## Alternatives

Limit: this reaches 32 bits only. `i64` needs eight registers and remains
unsupported. Tests: not recorded.
