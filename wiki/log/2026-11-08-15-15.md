# Verify memory runtime object isolation (sangoku-9bq.1)

_2026-11-08 15:15_

Bookkeeping, no code change. `sangoku-9bq.1` (P2) was filed after the
`sangoku-57q.6` intrinsic call audit found that `__gbc_memset`, `memmove` and
`memcpy` all selected `runtime/memory.asm` as one object, so a fill-only ROM
carried copy and move code. It asked to split `memset` into its own object while
retaining the shared copy/move body. Acceptance: a fill-only ROM omits
copy/move, a copy-only or move-only ROM omits fill, with overlap correctness,
zero lengths, symbol dependencies and assembly harness compatibility preserved.

It was already implemented by the memory size/speed split and runtime family
reorganization: `memcpy`, `memmove` and `memset` each have independent objects
under `runtime/memory/`, and the registry selects one variant at each
optimization level. Separate tuned copy/move implementations supersede the
original proposal to retain one shared copy/move body.

```text
helper   size bytes  speed bytes
memcpy   32          57
memmove  56          114
memset   24          43
```

The three current size objects total 112 bytes and speed objects total 214.
Fill-only linkage therefore retains 24/43 bytes instead of those combined
bundles, avoiding 88/171 unrelated bytes; copy-only retains 32/57 and move-only
56/114. These compare current independent objects against linking all three, not
against a historical version of `memory.asm`.

Validation: five targeted nextest checks pass in 0.39 seconds. Existing memory
tests cover overlap, zero lengths, stack/argument preservation and size/speed
tradeoffs; the linker selection test checks exact one-object selection for each
memory entry at all six optimization levels. Also assembled and linked each of
the six files alone with `rgbasm`/`rgblink` in a temporary directory, checking
its symbol file for the requested entry and absence of the other two, which
verifies actual ROM object isolation without building core or application
startup. Assembly harness compatibility is exercised by `tests/memory.rs`.
`cargo clippy --allow-dirty --fix` and `cargo fmt` pass. No runtime or backend
changes were required.
