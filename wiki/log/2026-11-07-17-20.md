# Core linking moves into the sangoku binary

_2026-11-07 17:20:00_

sangoku-30k.9.1.14: tools/link*core.py is deleted; sangoku build does the work. New src/link.rs holds the pure logic with unit tests: splitting assembly into sections, reachability from \_\_rust_gbc_main (any identifier another section defines counts as a reference, local .labels ignored), parsing the rgblink map for section sizes and free ROM0, placing sections into ROM0 then ROMX, and choosing runtime objects, which replaces the needs*\* checks in main.rs. build_rom now always compiles core and compiler_builtins to assembly and metadata once per opt level into build/core/opt-N (rebuilt when the backend library is newer), compiles the program against that metadata so symbol hashes match, prunes, probes sizes with an all-ROMX link, places, and links with rgblink -t. no_core programs need no special case: nothing from core survives pruning if nothing references it. First build pays about 26 s for core; later builds of a core-using program take about 1.3 s. tests/core_link.rs runs the real binary. Cache staleness only tracks the backend library, not edits to the core sources. No push.
