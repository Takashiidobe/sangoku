# Soft-float f32 add/sub/mul/cmp/min/max (sangoku-7qz.8.2)

_2026-11-07 02:40_

## Context

The LR35902 has no floating point, so `f32` arithmetic must be a runtime
library. sangoku-7qz.8.2 (P0) asked for `runtime/softfloat32.asm` with correctly
rounded add/sub/mul, `fcmp` ordering classes mapped to `FloatCC`, and
`fmin`/`fmax` with NaN rules, tested against host `f32` for NaN, inf, subnormal
and signed zero.

## Case

`a + b`, `a - b`, `a * b`, `a < b`, `a.min(b)` on `f32`.

## Before

`f32` arithmetic, `fcmp`, `fmin`/`fmax` unsupported.

## After

All lower to libcalls into `softfloat32.asm`; bit-exact with the host.

## How

- Runtime uses WRAM state, so it is not reentrant. Mantissas are held as
  `significand<<7` so the low 7 bits are guard/round/sticky; one shared
  `sf_roundpack` does subnormal shifting, round-to-nearest-even, overflow to inf
  and packing for add and mul. `mul` is a 24x24 shift-add loop.
- Libcalls `GbcFadd32`/`Fmul32`/`Fcmp32`/`Fmin32`/`Fmax32` (plumbed through
  `libcall.rs`, module naming, rgbds map). `fsub` is `fadd` with the sign byte
  xored inline. `fcmp` takes a class mask (eq/lt/gt/uno bits) as a third `i8`
  argument and the runtime shifts out the answer, so every `FloatCC` is one
  libcall.
- `fmin`/`fmax` follow Cranelift: NaN if either is NaN, -0 < +0.
- Tests: `lowered.rs` `f32_arithmetic_and_compares_match_host` (22 edge/random
  values, all pairs, 5 ops + 14 `fcmp` conds) and
  `f32_rounding_matches_host_on_random_operands` (600 pairs with nearby
  exponents and subnormal-range products). NaN compared by `is_nan`, everything
  else bit-exact. An expectation was sabotaged once to confirm the test really
  runs the runtime.

## Alternatives

Left: `fdiv`/`fsqrt`/rounding (8.3), conversions (8.4), `f16` (8.5). NaN results
are always the canonical qNaN.
