# CLIF lowering coverage matrix

Issue sangoku-7qz.1. tools/coverage_matrix.py generates one tiny CLIF function
per (op, type) for i8-i128 and f16-f128, lowers each with the new
`sangoku-lower --probe` mode (one result per function: ok, unsupported,
verifier, inexpressible, panic, invalid) and writes tests/coverage/lower.md
and lower.tsv. tests/coverage.rs runs `--check`, so the matrix must be
regenerated when lowering changes. Memory ops use i16 addresses.

Probe runs with the verifier off (as release cg_clif does) and again with it
on; ops that only lower because the verifier is off are listed separately.

Findings, 2026-11-06 (88 ok, 471 unsupported, 6 not expressible, 2 crashes):
- i8 is thin: no bnot, select, imul, shifts, min/max, bit counting.
- i32 has no mul/div/rem, signed ops, shl/rotates, extends, bit counting.
- i32 load/store crash in register allocation (SSA error), found by the matrix.
- i64, i128 and every float op are unsupported; so are all conversions.
- 16-bit addresses violate iAddr ints(32..64): load/store/func_addr/
  stack_addr/call_indirect only work with the verifier disabled.
- overflow ops are unsupported at every width.
