# CLIF lowering coverage matrix (sangoku-7qz.1)

_2026-11-06 20:10_

## Context

Nobody knew which CLIF ops the LR35902 backend could lower, and Rust `core`
needs most of them. Probing by hand for `i32` had already found `imul`, `udiv`,
`urem`, `sdiv`, `srem`, `ishl`, `sshr`, `rotl`, `rotr`, `smin`, `umax`, `iabs`,
`popcnt`, `clz`, `ctz`, `bswap`, `bitrev`, `sextend` and variable `ushr`
unsupported. sangoku-7qz.1 (P0) asked for a generated op x type matrix, checked
in, bounded and run under nextest, so the gaps drive the other tickets and CI
fails on regressions. This is the tool that produced the ticket list for the
rest of the 7qz epic.

## Case

`tools/coverage_matrix.py` generates one tiny CLIF function per (op, type) for
`i8`-`i128` and `f16`-`f128`. Memory ops use `i16` addresses.

## Before

No inventory of supported ops; gaps were found by trial and error.

## After

`sangoku-lower --probe` lowers each function and prints one result: `ok`,
`unsupported`, `verifier`, `inexpressible`, `panic` or `invalid`. Output goes to
`tests/coverage/lower.md` and `lower.tsv`. Probe runs with the verifier off (as
release `cg_clif` does) and again with it on; ops that only lower with the
verifier off are listed separately. Findings on 2026-11-06 (88 ok, 471
unsupported, 6 not expressible, 2 crashes):

- `i8` is thin: no `bnot`, `select`, `imul`, shifts, min/max, bit counting.
- `i32` has no mul/div/rem, signed ops, `shl`/rotates, extends, bit counting.
- `i32` load/store crash in register allocation (SSA error).
- `i64`, `i128` and every float op are unsupported, and so are all conversions.
- 16-bit addresses violate `iAddr` `ints(32..64)`: `load`/`store`/`func_addr`/
  `stack_addr`/`call_indirect` only work with the verifier disabled.
- overflow ops are unsupported at every width.

## How

`tests/coverage.rs` runs `--check`, so the matrix must be regenerated whenever
lowering changes.

## Alternatives

None recorded. Findings were filed as sibling tickets.
