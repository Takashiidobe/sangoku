# Phase 1: standalone Rust frontend with FileCheck fixtures (sangoku-1uz)

_2026-11-06 16:57_

## Context

The compiler was one long pipeline (rustc, Cranelift, LR35902 lowering, RGBDS,
link), so every experiment waited on all of it. `sangoku-1uz` (P0) is phase 1 of
five (1 frontend, 2 CLIF gen, 3 lowering, 4 asm/objects, 5 link/execute): make
the pinned rustc fork runnable alone on a `.rs` file and save MIR so later
phases can be tested without it. The existing ROM command keeps running stages
together.

## Case

`sangoku frontend <source.rs> [output.mir|-]`. Plain `--emit=mir` trips the LLVM
data-layout check for the `lr35902` target, so that route fails.

## Before

No way to run just the frontend; `--emit=mir` fails on the LLVM data-layout
check (exact error text not recorded).

## After

The command runs rustc with `-Zunpretty=mir` and saves MIR (default
`build/<name>.mir`). It needs no codegen backend, avoiding the data-layout
check. Paths are remapped to `.` so output is machine independent.

## How

- rustc setup is shared with `build` via `rustc_command`.
- Fixture types are subdirectories of `tests/fixtures`; `mir` is first, with
  return-const, add, branch and call. Expectations are `// CHECK` lines written
  by `tools/update_filecheck.py` (follows nassau): regenerate with no arguments
  or a glob, verify with `--check`; `cargo test --test filecheck` runs it. New
  phases add an entry to `STAGES` in the tool. Requires FileCheck on `PATH`.
- README: audit sections removed, testing condensed to the FileCheck workflow.
  Audit code and `wiki/audits` untouched.

## Alternatives

Phase 2 consumes Rust source in-process rather than this saved MIR (see
`sangoku-f12`).
