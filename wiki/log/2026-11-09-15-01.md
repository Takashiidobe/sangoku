# inc/dec for constant steps (sangoku-2mv)

_2026-11-09 15:01:33_

## Context

The regalloc audit against SDCC showed `p.add(1)` lowering to `ld l,1; ld h,0`
plus add/adc through `A` (8 instructions) instead of `inc rr`, and `n -= 1`
lowering to `ld b,1; ld a,..; sub b` instead of `dec r`. The constant registers
also competed for the 7 byte registers, which is where most of the win came
from. sangoku-2mv lowers constant +-1 to `inc`/`dec`. Harness total 1153 -> 942
bytes (2.71x -> 2.21x of SDCC): `copy_u8` 130 -> 53, `fill` 43 -> 27, `strlen16`
64 -> 33, `count_eq` 104 -> 77, `sum_u8` 104 -> 75, `max_u8` 78 -> 69, `sum_u16`
133 -> 117, `fib16` 40 -> 34. The `sum_u8`/`count_eq` regressions from
sangoku-dq5 are gone.

## Case

`iadd`/`isub` by +-1, 8- and 16-bit (either operand order for `iadd`): pointer
increments such as `p.add(1)` and loop counters such as `n -= 1`.

## Currently emits

```asm
ld l, 1
ld h, 0
; add/adc through A
```

and for bytes `ld b, 1` / `ld a, ..` / `sub b`.

## Should emit

```asm
inc r         ; byte
dec r
inc rr        ; word in BC/DE/HL
```

When the word is not in a register pair:

```asm
inc lo        ; increment
jr nz, @+3
inc hi

inc lo        ; decrement
dec lo        ; sets Z from lo == 0 without using A
jr nz, @+3
dec hi
dec lo
```

## How

New `IncDec8`/`IncDec16` (`inst.isle`, `unit_step` in `lower.rs`,
`inst/emit.rs`, `inst/mod.rs`). Operands are `use(src)` + `reuse_def(dst)`, so
there is no move and no `A` clobber.

Tests: full default `cargo nextest` passed (210) after the lowering change,
before the final unit-test and format-only edits. New emulator tests
`unit_steps_carry_across_byte_boundaries` (word/byte steps across `0xFF`/`0x00`,
opt `0`/`2`/`z`, expects 243) and `pointer_loops` pass. The `lr35902` backend
unit tests (`cargo test -p cranelift-codegen --features lr35902 --lib lr35902`)
did not compile at HEAD (missing imports in the `emit.rs` test module); fixed
the imports, added encoding/printing tests, and changed
`compiles_i16_arithmetic...` to add `0x0102` since its `+1` now becomes `inc`.

## Alternatives

Not done:

- Word `inc` still goes through a scratch pair then moves back instead of
  `inc de`.
- A no-op `ld a, a` after `ld a, [de]`, and `ld a, b; or a` after `dec b` (noted
  on sangoku-1de / sangoku-i70).
- Other constant adds still use a register; an `add a, n` immediate form is a
  possible follow-up.
- No cycle measurement.
