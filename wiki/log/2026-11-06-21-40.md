# Allow 16-bit addresses in CLIF and enable the verifier

Issue sangoku-7qz.6. cranelift meta shared/instructions.rs defined both iAddr
type variables as ints(32..64); 16-bit pointers failed the verifier, so the
release backend ran with enable_verifier off. Both now use ints(16..64). Other
targets still fail the separate "invalid pointer width" check for 16-bit values.

cg_clif's enable_verifier() now returns true for z80, which also turns on the
regalloc checker. Blank ROM and all fixtures pass with it on.

Coverage matrix: nothing is rejected by the verifier any more; func_addr,
stack_addr and call_indirect became expressible and lower. br_table needs an i32
index (verifier), so the matrix probes it at i32. Remaining memory gaps (offsets
beyond -128..127, uload/sload/istore) are a new ticket.
