# Bounded inline versus helper copy and fill comparison (sangoku-mt4.5.5)

_2026-11-08 11:58:46_

## Context

Memory audit (`sangoku-mt4.5`). The user asked for a small comparison, not the
full audit: lengths 1/2/4/8/16, inline versus both helper variants, no global
threshold. No compiler policy changed.

## Case

Explicit inline `i16` chunks (`i8` at length 1) versus `memcpy`/`__gbc_memset`
calls. This probes optimized CLIF backend output, not the Rust intrinsic
inlining heuristic. Dynamic destination only; source `$c400`, fill `0xa5`;
`$c100`/`$c1ff` destinations cost the same; pointer returns unused.

## Currently emits

Not a code change. Entry-through-`RET` T-cycles (spills, argument packing,
helper `CALL`/`RET`, cleanup, frames; common outer `CALL` excluded):

```text
bytes  cp inline  cp size  cp opt  fill inline  fill size  fill opt
1            152      460     504           56        612       656
2            224      512     540          148        668       676
4            456      616     596          204        780       700
8            936      824     708          364       1004       748
16          2280     1240     932          916       1452       844
```

## Should emit

Inline ROM bytes copy/fill for 1/2/4/8/16: 25/10, 35/23, 71/32, 143/56, 335/134.
Helper callers cost 30 bytes (copy), 55 (fill), any length; add helper ROM once
per program: copy 32/57, fill 24/43 (size/opt). Peak stack incl. outer return
address: inline copy 4/6/10/10/10, inline fill 2/4/4/4/6, helper copy 13, helper
fill 13/15 (size/opt). No table/scratch RAM.

## How

`cargo run --example audit-memory-inline` writes `build/memory-inline/`
(`callers.clif`, `results.json`, `size/`, `opt/`: inputs, assembly, helper
copies, linker maps, hashes, assembler versions, revisions). 80 checks pass (5
lengths, 2 ops, 2 helper variants, 2 alignments) on destination/source/guard
bytes and restored `SP`. 19 targeted nextest tests, clippy, `cargo fmt`, LSP and
`git diff --check` pass. No backend/runtime edits.

## Alternatives

Inline copy wins cycles at 1-4 bytes, helpers at 8/16. Inline fill wins through
8; the opt helper wins at 16, while the size helper trades speed for ROM there.
Backend spill/frame cost makes 16-byte inline copy 335 bytes. These are sampled
crossovers, not thresholds. Retain both; defer threshold changes until the
lowering policy is checked. Broader audit tasks remain open.
