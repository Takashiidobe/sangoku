# Bounded memory-offset address emission (sangoku-9uq)

_2026-11-08 21:24_

## Context

`let_down` assembly used 30 consecutive `inc hl` for a `base+30` access.
`sangoku-9uq` (P2) asked for `ld hl, imm; add hl, bc` for larger offsets in both
machine bytes and RGBDS output, keeping the cheaper paths for 0/+1/-1. Result:
for +30, address setup drops from 32 to 4 bytes and 248 to 20 T-cycles (copies
included). These are instruction costs, not a whole-program benchmark.

## Case

A CLIF load/store at `base+30` (`BC` base, address in `HL`).

## Currently emits

```asm
ld h, b
ld l, c
inc hl ; 30 times
```

## Should emit

```asm
ld hl, $001E
add hl, bc
```

Offsets 0 and +-1 keep the copy plus `inc`/`dec`; larger offsets wrap to 16
bits.

## How

Both RGBDS printing and machine emission use the new sequence; ISLE and register
allocation constraints are unchanged: `BC` is the fixed base, `HL` and `A` are
already early-clobbered scratch registers. The sequence preserves `BC`, `A` and
`DE`; no flags value is carried between these operations.

Regenerated default-opt `let_down.asm`
(`cargo run -- asm examples/let_down.rs`): `inc hl` count 2915 -> 251, longest
consecutive run 49 -> 1; the old site prints `ld hl, $001E; add hl, bc`; 139
`add hl, bc` address calculations.

Tests: new bounded CLIF test in `tests/lowered.rs` (`memory_offsets`) checks 14
offsets (0, +-1, +-2, +-30, +300, -200, 32768, 65535, 65536, `i32::MIN`/`MAX`)
with targets `C0FF`/`C100`, 16-bit loads and stores, a live base after stores
and SP restoration. Existing tests cover 8/16/32-bit loads/stores and
extensions; backend tests check emitted bytes and sequences. 38 focused backend
tests and both memory-offset tests pass; `hello.gb` smoke build succeeds. No
emulator changes. Clippy, fmt, LSP diagnostics and diff checks pass.

## Alternatives

None recorded. Cold standalone-lower recompilation makes the first integration
run slower; warm checks finish below 10 seconds.
