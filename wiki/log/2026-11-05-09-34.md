# Cranelift 9242820f — Lower basic LR35902 integer functions

_2026-11-05 09:34:05_

## Context

The pipeline (`903832fa`) and ABI (`bd158544`) existed, but no CLIF opcode
lowered, so no function produced machine code. Commit `9242820f` (Cranelift
fork, `third_party/wasmtime`) produces the first machine-code result from a
simple integer function. No bead id is recorded.

## Case

An `i8` function that adds two constants and returns (test
`compiles_i8_add_and_return_to_lr35902_machine_code`).

## Before

Every instruction fell through as unsupported.

## After

I8 constants, returns and addition lower in `isa/lr35902/lower.rs`:

```rust
Opcode::Iadd if ctx.output_ty(ir_inst, 0) == types::I8 => {
    let lhs = ctx.put_input_in_regs(ir_inst, 0).only_reg()?;
    let rhs = ctx.put_input_in_regs(ir_inst, 1).only_reg()?;
    let dst = ctx.alloc_tmp(types::I8).only_reg()?;
    ctx.emit(Inst::Add8 { dst, lhs, rhs });
    Some(smallvec![ValueRegs::one(dst.to_reg())])
}
```

## How

The lowerer allocates I8 temporaries, emits immediate loads and `Add8`, and
routes return values through the ABI. `inst/emit.rs` inserts moves into and out
of `A` only when operands are elsewhere. Tests: the add/return test asserts the
last emitted byte is `0xC9` (`ret`); `compiles_i8_add_with_spills` sums twelve
constants (register pressure), expects a `0xF8` byte (stack-pointer-relative
spill code) and a trailing `0xC9`.

## Alternatives

This is an I8 bootstrap slice, not general CLIF support; all other operations
stay unsupported and fall through.
