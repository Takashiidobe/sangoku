# Cranelift c7aa4db5 — Lower 16-bit arithmetic and bitwise operations

_2026-11-05 11:53:07_

## Context

Pointers and many `core` integer routines are 16-bit, but the CPU only has 8-bit
ALU operations. Until `I16` lowered, anything beyond bytes failed in the
backend. Commit `c7aa4db5` in Cranelift (`third_party/wasmtime`); no bead.

## Case

```text
iadd / isub / band on I16
```

## Before

Only `I8` operations lowered.

## After

`I16` values live in `ValueRegs::two(low, high)`, with carry/borrow between
bytes:

```asm
add a, <rhs_low>     ; ADD  (0x80)
adc a, <rhs_high>    ; ADC  (0x88)
sub <rhs_low>        ; SUB  (0x90)
sbc <rhs_high>       ; SBC  (0x98)
```

Exact registers depend on allocation. Bitwise ops run independently on each
byte.

## How

`lower.rs` builds the pair; `Add16`/`Sub16` in `inst/mod.rs` and `inst/emit.rs`
use `emit_accumulator_op` for each half and fix the accumulator to `A` as an
early def. Pretty printing writes `add a, r` / `adc a, r`. Test
`compiles_i16_arithmetic_and_bitwise_ops_to_lr35902_machine_code` checks for
`ADC` (`0x88..=0x8F`) and `SBC` (`0x98..=0x9F`) opcodes and a final `ret`
(`0xC9`).

## Alternatives

This is bytewise support for the 8-bit CPU, not native I16 arithmetic; it builds
on the existing register allocator. Other I16 operations are not covered by this
commit.
