# Cranelift 452f971a — Keep spill slots clear of outgoing arguments

_2026-11-05 11:16:02_

## Context

Once calls could pass stack arguments (`6b0dd373`), the frame reserved an
outgoing-argument area, but spill slots were still addressed from offset 0. On a
CPU with 7 byte registers spills are frequent, so a spill could land on top of
an argument being prepared for the callee. Commit `452f971a` in Cranelift
(`third_party/wasmtime`); no bead.

## Case

A call with stack parameters in a function that also has spilled locals.

## Cause

`stack_mode_offset` treated `Slot` and `OutgoingArg` identically:

```rust
StackAMode::Slot(offset) | StackAMode::OutgoingArg(offset) => offset as i32,
```

so slot 0 and outgoing argument 0 shared the same address. No failing output was
recorded; the symptom is the overlap itself.

## Fix

`cranelift/codegen/src/isa/lr35902/inst/mod.rs`: slots are shifted past the
outgoing area.

```rust
StackAMode::Slot(offset) => {
    offset as i32 + frame.map_or(0, |frame| frame.outgoing_args_size as i32)
}
StackAMode::OutgoingArg(offset) => offset as i32,
```

No regression test is part of the commit.

## Alternatives

None recorded.
