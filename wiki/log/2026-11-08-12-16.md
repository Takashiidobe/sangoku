# Split 32-bit population count by size and speed (sangoku-s6z)

_2026-11-08 12:16:09_

## Context

Native 16-bit popcount already splits size/speed and the 16-bit inline
implementation distinguishes optimization intent, but `__gbc_popcnt32` was one
helper that used per-byte shift loops, not parallel counting. `sangoku-s6z`
splits it into independently selected runtime helpers (compact for `s`/`z`,
table-free bytewise parallel counting for `0`-`3`) while preserving the ABI,
wide callers and the zero-extended return.

## Case

`u32::count_ones` (`__gbc_popcnt32`).

## Currently emits

One helper with per-byte shift loops, linked at every optimization level; its
size/cycle figures were not recorded in the original log. The old helper's
listing is not recorded.

## Should emit

```text
variant   helper ROM bytes  entry-through-RET T-cycles
compact   25                1856
parallel  112               468
```

Both have input-independent timing, zero table bytes, no scratch RAM and zero
additional stack use (3 bytes including the incoming argument and return). These
are helper costs; generated caller costs depend on register allocation.

## How

`s`/`z` select `popcnt32_size.asm`: shift a 32-bit register chain 32 times,
adding each shifted-out bit to `A`. `0`/`1`/`2`/`3` select `popcnt32_opt.asm`:
unrolled bytewise parallel counting, reusing the table-free algorithm from the
16-bit audit. Only the requested variant is linked; `runtime/wide32.asm`, used
by assembly test harnesses, includes the optimized implementation. The ABI
remains `B`/`C`/`A` plus the fourth input byte on the stack; the result is
returned in `A` with `B`/`C`/`D` zero. Registers are caller-saved, the caller
retains the stack argument, and both variants write no memory and allocate no
stack.

Tests: 142 bounded inputs per variant (zero/all ones, every set/clear bit,
representative bytes in all positions, alternating patterns, 40
seed-`0x706f7063` random values) verify host `count_ones`, zero extension, SP,
untouched argument/canaries, no writes, constant cycles and the ROM/speed
tradeoff. Linker unit tests select exactly one helper at all six optimization
levels. Real Rust `u32` `count_ones` ROMs execute at `0`/`2`/`z` with unrelated
helpers excluded. Reproduce:
`cargo nextest run --no-fail-fast -E 'binary(popcount32)' --success-output immediate`.

Validation: `cargo nextest run --no-fail-fast` (175 passed, 17 profile
exclusions). Extensive: `split_i64_values_match_host`,
`split_i128_values_match_host` and
`upstream_u64_decimal_formatting_matches_host` passed. Smoke:
`cargo run -- build examples/hello.rs build/hello.gb` passed.
`cargo clippy --allow-dirty --fix`, `cargo fmt`, LSP diagnostics and
`git diff --check` pass. No vendored compiler/backend sources changed.
