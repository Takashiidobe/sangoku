# Split 32-bit population count by size and speed

_2026-11-08 12:16:09_

sangoku-s6z: Split \_\_gbc_popcnt32 into independently selected runtime helpers.
The old 32-bit helper used per-byte shift loops, not parallel counting.
The 16-bit inline implementation already distinguishes optimization intent.

s/z select popcnt32_size.asm: shift a 32-bit register chain 32 times, adding
each shifted-out bit to A. 0/1/2/3 select popcnt32_opt.asm: unrolled bytewise
parallel counting, reusing the table-free algorithm from the 16-bit audit.
Only the requested variant is linked. runtime/wide32.asm, used by assembly
test harnesses, includes the optimized implementation.

The ABI remains B/C/A plus the fourth input byte on the stack; the result is
returned in A with B/C/D zero. Registers are caller-saved. The caller retains
the stack argument. Both variants write no memory and allocate no stack.

| Variant  | Helper ROM bytes | Entry-through-RET T-cycles |
| -------- | ---------------- | -------------------------- |
| compact  | 25               | 1856                       |
| parallel | 112              | 468                        |

Both have input-independent timing, zero table bytes, no scratch RAM and zero
additional stack use (3 bytes including the incoming argument and return).
These are helper costs; generated caller costs depend on register allocation.

Reproduce: cargo nextest run --no-fail-fast -E 'binary(popcount32)' --success-output immediate
142 bounded inputs per variant cover zero/all ones, every set/clear bit,
representative bytes in all positions, alternating patterns and 40 seed-
0x706f7063 random values. Tests verify host count_ones, zero extension, SP,
untouched argument/canaries, no writes, constant cycles and ROM/speed tradeoff.
Linker unit tests select exactly one helper at all six optimization levels.
Real Rust u32 count_ones ROMs execute at 0/2/z with unrelated helpers excluded.
