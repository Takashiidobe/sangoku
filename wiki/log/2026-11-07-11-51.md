# LR35902 numeric conversion legalization (sangoku-7qz.9.7)

_2026-11-07 11:51:19_

## Context

`sangoku-7qz.9.7` (P0): the conversion matrices in `tests/coverage/lower.md`
still showed unsupported casts between integer widths (including i64/i128) and
f16/f32/f64/f128, so those Rust `as` casts could not lower. The frontend also
rejected scalar-float MIR outright. All applicable paths now lower and link.

## Case

Rust casts such as `*memory as f16` (`i64_to_f16`), `u64_to_f32`, `i128_to_f64`,
`u128_to_f128`, `f64_to_i8`, `f128_to_u128`, `f64_to_f16`, `f16_to_f128`,
`f128_to_f32`, in `examples/conversions.rs` and
`tests/fixtures/clif/conversions.rs`.

## Before

Unsupported cells in the conversion matrices; scalar-float MIR gated off in
cg_clif (not recorded: exact error text).

## After

Bounded emulator references (`tests/fixtures/emulate/wide-convert.clif`, cases
generated by `tools/generate_conversion_cases.py`) and Rust conversion fixtures
pass at none/speed. Final `cargo nextest run --no-fail-fast`: 109 passed, 0
skipped. Conversion and blank ROM builds pass; clippy and fmt pass.

## How

- Byte-array conversion runtime `runtime/convert.c` (checked-in
  `runtime/convert.asm`, `tools/generate_convert.py`) with single rounding and
  explicit trap status. A stack context holds 16 source bytes, 16 result bytes,
  widths, a mode byte and a status byte; no mutable global state.
- 17-byte significand retains every i128 input bit and binary128 significand
  bit; narrowing rounds once, ties to even, with no intermediate f32/f64.
- Trapping casts check the status; saturating casts clamp and map NaN to zero.
- Routed Rust casts through CLIF and removed the obsolete scalar-float MIR gate.
- Expanded coverage probes and marked extending-load type exclusions (i128)
  accurately.
- Refreshed the pre-existing stale f128 assembly (`runtime/softfloat128.asm`)
  from its unchanged C source. Rebuilt cg_clif. Committed wasmtime `00b9a99a`
  and cg_clif `262968c`; no push.
