# Undefined libcall check for compiler_builtins (sangoku-30k.9.1.5)

_2026-11-07 15:10_

## Context

`core` references `__udivti3`-style `i128` libcalls that looked undefined, but
`sangoku-30k.9.1.5` found it was not a libcall-mapping gap: `compiler_builtins`
implements `__udivti3`, `__umodti3`, `__divti3`, `__modti3`, `__multi3`,
`__rust_u128_mulo` and `__rust_i128_mulo`. Our manual rustc invocation set only
`feature=compiler-builtins`; Cargo's implied feature `unmangled-names` was
missing, so the symbols came out Rust-mangled and references stayed undefined.
What was missing was a check.

## Case

`tools/core_report.py` building `compiler_builtins` without and with
`--cfg feature=unmangled-names`.

## Before

Without the cfg the report lists `__divti3`, `__udivti3`, `__umodti3`,
`__rust_u128_mulo` and `memcmp` as undefined. There was no check at all.

## After

With the cfg the list is empty.

## How

`tools/core_report.py` already built with `unmangled-names` and `mem`. It now
collects every non-colocated import (`fn = u0:N sigN ; "name"`) and every
defined `; symbol` across the core, `compiler_builtins` and driver CLIF, and
emits the difference as `undefined` (JSON output is now `{reports, undefined}`).
`core_lowers_to_lr35902_without_failures` asserts no undefined `__*ti3` or
`__*mulo` symbol. The `tests/core.rs` size-limit test builds only metadata and
needs no cfg.

## Alternatives

Decision on the bead: build `compiler_builtins` once (cached artifact keyed on
fork base plus backend) instead of per ROM; that stays with `sangoku-30k.9.1.8`,
which needs per-function sections first. Until then the report passes the cfgs
itself. Not pushed.
