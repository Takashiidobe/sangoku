# sangoku-d35 distribution: bundle versus integrated rustc driver

_2026-11-11 07:28:54_

- bead: sangoku-d35
- kind: bookkeeping
- area: distribution

Outcome: the distribution review distinguishes the existing single-file bundle
from a proposed executable with an integrated compiler driver.

The checkout already contains a Linux x86-64 packaging prototype that appends
the compiler, backend, loader, shared libraries, target libraries, and runtime
assets to a static launcher. First use extracts a content-addressed cache. RGBDS
remains external, and bundled compilation bypasses Cargo and rustup.

The proposed next architecture keeps the CLI and ROM orchestration while linking
the pinned rustc driver and Cranelift backend into the executable. The pinned
compiler exposes a backend factory callback for this integration. Static
compiler linkage is separate build work, not an automatic consequence of
embedding the driver. Host procedural macros still require dynamic loading.

Normal ROM builds currently invoke rustc separately for MIR, CLIF, and assembly.
Making debug dumps optional would remove repeated compilation from that path.
The standalone CLIF lowering tool is not part of the normal ROM build pipeline.

No compiler or application code changed. Clippy and formatting were run. The
existing distribution artifact and isolation test were inspected, but the
artifact was not rebuilt or smoke-tested during this architecture review.
