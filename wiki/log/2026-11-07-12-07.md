# Restore upstream core for LR35902 (sangoku-30k.4)

_2026-11-07 12:07:08_

## Context

`sangoku-30k.4` (P0): the Rust fork carried `target_arch = "z80"` gates in
`library/core` (formatting stubs, numeric API gates, module exclusions) that hid
APIs the target could not yet compile. They change language-visible behavior,
and the wide-type legalization (`sangoku-7qz`) had made most of them
unnecessary. Done under the explicitly confirmed personal-fork/no-upstream
exemption; the overlapping `sangoku-30k.6` audit is also covered.

## Case

Baseline target core metadata compilation failed on the disabled
`carrying_mul_add` (gated `u64::carrying_mul_add`). Restored source passed that
same frontend check.

## Before

16 modified `library/core` files diverging from upstream, with formatting stubs,
numeric API gates, module exclusions, simplified panic text, pointer special
casing and an extra intrinsic inlining attribute.

## After

All 16 files restored byte-for-byte from upstream base `2d20b42b883`; no core
z80 cfg gates remain. New regression
`target_core_preserves_upstream_api_surface` (`tests/core.rs`,
`tests/fixtures/core/restored-apis.rs`) compiles core metadata for the 16-bit
target and checks formatting traits, wide arithmetic, wrappers, time and random
APIs. Full stage-2 compiler/library rebuild, toolchain relink and cg_clif
rebuild pass; all 111 nextest tests pass. Clippy, fmt, LSP diagnostics and the
blank-ROM smoke check pass. Rust commit `d2da96af733`.

## How

Removed the gates and documented each disposition and the remaining C ABI
classifier in `wiki/concepts/rust-fork.md`; added a README note that core stays
unchanged.

## Alternatives

Not done: full core/alloc code generation (`sangoku-30k.9`), formatting
execution (`sangoku-30k.5`) and broader 16-bit pointer validation
(`sangoku-30k.7`) remain separately tracked. No push.
