# Cranelift 2889e764 — Limit memcpy chunks to pointer width

_2026-11-05 15:05:05_

## Context

Cranelift's frontend expands small constant-size copies inline, choosing an
integer load/store type from the byte count with host-width assumptions. On a
16-bit-address target that produced `i64` loads and stores, which the
byte-register backend cannot represent. Commit `2889e764` in Cranelift
(`third_party/wasmtime`).

## Case

A small constant-size memory copy, for example 24 bytes.

## Before

Accesses over 8 bytes used 8-byte chunks, so `I64` loads and stores.

## After

The new test `small_memcpy_uses_pointer_sized_chunks` (U16 pointers) verifies a
24-byte copy uses twelve `I16` loads and stores and never emits `I64`.

## How

`cranelift/frontend/src/frontend.rs` caps the chunk size at the target pointer
width before picking the type (threshold now in bytes, `THRESHOLD_BYTES` = 32);
larger copies fall back to the memcpy path:

```rust
let access_size = access_size.min(u64::from(config.pointer_bytes()));
let int_type = Type::int((access_size * 8) as u16).unwrap();
```

This fits copy lowering to the 16-bit address model and the four-byte value
representation.

## Alternatives
