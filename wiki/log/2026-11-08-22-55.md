# Add runtime/vec FixedVec crate and move audio player into runtime/audio

_2026-11-08 22:55:12_

Two runtime library crates now link into programs the way sangoku_console does. Both are listed in src/console.rs (FILES, externs, assembly, cache inputs, crate build list) and in tools/bundle_toolchain.py, so adding a runtime crate is now a handful of one-line entries. The per-crate rustc flag conditions in console.rs no longer assume every crate other than ufmt_write needs ufmt.

runtime/audio (sangoku_audio): examples/audio/player.rs moved with git mv to runtime/audio/src/lib.rs. The five audio examples and the song files use sangoku_audio:: paths instead of a #[path] module, and tests/audio.rs depends on the crate. Building the same five examples from HEAD and from the new tree with one compiler: every ROM is 196 bytes smaller used, and not byte-identical (symbol hashes and section order change). The cause of the 196 bytes was not investigated. The audio tests are host-side score checks; the ROMs were not run in an emulator or listened to.

runtime/vec (sangoku_vec): FixedVec<T, N> with inline storage, push returning Err(value) when full, pop, clear, len, capacity, is_empty, as_slice, Deref to a slice, IntoIterator for references, and a Drop that drops initialized elements. tests/vec.rs covers capacity, order, slice access, and drop counts on pop, clear, drop and a rejected push. examples/fixed_vec.rs runs in the emulator and returns 30.

Sizes at opt z for two pushes and a sum: alloc::Vec 12,498 bytes, heapless::Vec<u8,16> 0.9.3 3,035, a single-file FixedVec 1,763, sangoku_vec 1,976. heapless is larger because its storage- and length-generic VecInner leaves non-inlined push, deref and index functions. Measured for u8 and N=16 only. The heapless build used a rustc wrapper script and hand-compiled hash32/byteorder/heapless, since the driver cannot take extra user crates. Details are in wiki/concepts/fixed-vec.md (new, indexed).

Also fixed benchmarks/size_baseline.py, which never passed --alloc for the heap row and so read a stale probe.map; the earlier heap numbers were wrong at opt 0 (now 30,316; z is 24,975) and size-baseline.md has the refreshed table and an alloc breakdown: 12 KB of the 17 KB of alloc is Global and &BumpAllocator instantiations of RawVecInner, and 77% of finish_grow is ld instructions (spills). Regenerated five lower FileCheck fixtures with tools/update_filecheck.py after earlier lowering changes.

Full default nextest run: 201 passed. Not done: opt 1/2/3/s size rows, a vec-with-larger-N size check, packaging heapless as a user crate. No push.
