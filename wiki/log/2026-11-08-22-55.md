# Add runtime/vec FixedVec crate and move audio player into runtime/audio (sangoku-iw3, sangoku-42r)

_2026-11-08 22:55:12_

## Context

Audio examples included `audio/player.rs` through `#[path]`. `sangoku-42r` made
it a runtime crate (`sangoku_audio`) linked like `sangoku_console`;
`sangoku-iw3` added a fixed-capacity vector crate `sangoku_vec` with an example,
host tests and a size comparison against `alloc::Vec` and `heapless`.

## Case

Fixed-capacity `Vec`-like storage; the audio player was a `#[path]` include, not
a linked crate.

## Before

`alloc::Vec` is 12,498 B for two pushes and a sum at opt `z`; no fixed-capacity
crate existed.

## After

Same workload at opt `z` (`u8`, `N=16` only):

```text
heapless::Vec<u8,16> 0.9.3 3,035 B
single-file FixedVec       1,763 B
sangoku_vec                1,976 B
```

`heapless` is larger because its storage- and length-generic `VecInner` leaves
non-inlined push, deref and index functions. Details in
`wiki/concepts/fixed-vec.md` (new, indexed). Full default nextest run: 201
passed.

## How

- Both crates are listed in `src/console.rs` (FILES, externs, assembly, cache
  inputs, crate build list) and `tools/bundle_toolchain.py`; the per-crate rustc
  flag conditions no longer assume every crate but `ufmt_write` needs `ufmt`.
  Regenerated five lower FileCheck fixtures with `tools/update_filecheck.py`.
- `runtime/audio`: `git mv` of the player to `runtime/audio/src/lib.rs`; the
  five audio examples and song files use `sangoku_audio::` paths;
  `tests/audio.rs` depends on the crate. Building the five examples from HEAD
  and the new tree with one compiler: every ROM is 196 bytes smaller used and
  not byte-identical (symbol hashes, section order). The cause of the 196 bytes
  was not investigated. Audio tests are host-side score checks; ROMs were not
  run in an emulator or listened to.
- `runtime/vec`: `FixedVec<T, N>` with inline storage, `push` returning
  `Err(value)` when full, `pop`, `clear`, `len`, `capacity`, `is_empty`,
  `as_slice`, `Deref` to a slice, `IntoIterator` for references, and a `Drop`
  for initialized elements. `tests/vec.rs` covers capacity, order, slice access
  and drop counts on pop, clear, drop and a rejected push.
  `examples/fixed_vec.rs` runs in the emulator and returns 30.
- Fixed `benchmarks/size_baseline.py`, which never passed `--alloc` for the heap
  row and read a stale `probe.map`; earlier heap numbers were wrong at opt 0
  (now 30,316; `z` is 24,975). `size-baseline.md` has the refreshed table and an
  alloc breakdown: 12 KB of the 17 KB of alloc is `Global` and `&BumpAllocator`
  instantiations of `RawVecInner`, and 77% of `finish_grow` is `ld` instructions
  (spills).

## Alternatives

Not done: opt 1/2/3/s size rows, a vec-with-larger-N size check, packaging
`heapless` as a user crate (its build used a rustc wrapper script and
hand-compiled `hash32`/`byteorder`/`heapless`, since the driver cannot take
extra user crates). No push.
