# Phase 2: standalone CLIF generation

Issue sangoku-f12. Adds `sangoku clif <source.rs> [output.clif|-]`: runs the
cranelift backend with `--emit=asm,llvm-ir` and `CG_CLIF_CLIF_ONLY=1`, and
saves the unoptimised CLIF of every function (with ABI and MIR comments) as one
file, default build/<name>.clif. The backend consumes MIR in-process, so the
input is Rust source, not the saved phase 1 MIR.

Backend change (third_party/rustc_codegen_cranelift, uncommitted in the
submodule): with CG_CLIF_CLIF_ONLY set, compile_cgu skips define_function so
lowering never runs; when IR output is requested, assembly-only modules write
their CLIF as the module's llvm_ir file (previously rustc failed copying a
missing .ll). `CodegenedFunction::write_clif` supports this.

tests/fixtures/clif: return-const, branch, call, bitand. update_filecheck.py
drops volatile lines (`set`, `; abi`, `; instance`) and masks crate hashes.
Add and overflow need a panic lang item to codegen, so bitand stands in.
Tests now run with `cargo nextest run --no-fail-fast`.
