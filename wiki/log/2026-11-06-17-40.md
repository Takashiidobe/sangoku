# Phase 2: standalone CLIF generation (sangoku-f12)

_2026-11-06 17:40_

## Context

Phase 2 of the five-phase split (`sangoku-f12`, P0): make MIR-to-Cranelift-IR
translation runnable alone and save textual CLIF per function, so phase 3
lowering can be tested from fixtures without rustc. Acceptance: deterministic
output loadable by phase 3.

## Case

`sangoku clif <source.rs> [output.clif|-]`. Because the backend consumes MIR
in-process, the input is Rust source, not the saved phase 1 MIR.

## Before

With `--emit=asm,llvm-ir`, assembly-only modules wrote no IR file, so rustc
failed copying a missing `.ll`; and lowering always ran, so there was no way to
stop at CLIF.

## After

The command runs the backend with `--emit=asm,llvm-ir` and `CG_CLIF_CLIF_ONLY=1`
and saves the unoptimised CLIF of every function (with ABI and MIR comments) as
one file, default `build/<name>.clif`.

## How

- Backend change in `third_party/rustc_codegen_cranelift` (uncommitted in the
  submodule at the time): with `CG_CLIF_CLIF_ONLY` set, `compile_cgu` skips
  `define_function` so lowering never runs; when IR output is requested,
  assembly-only modules write their CLIF as the module's `llvm_ir` file.
  `CodegenedFunction::write_clif` supports this.
- Fixtures in `tests/fixtures/clif`: return-const, branch, call, bitand.
  `update_filecheck.py` drops volatile lines (`set`, `; abi`, `; instance`) and
  masks crate hashes.
- Tests now run with `cargo nextest run --no-fail-fast`.

## Alternatives

Add and overflow fixtures need a panic lang item to codegen, so `bitand` stands
in.
