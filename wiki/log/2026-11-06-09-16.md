# Add division execution and runtime audit reporting (sangoku-mt4.1)

_2026-11-06 09:16_

## Context

To decide which runtime helpers are worth their bytes on a 32 KB ROM we need
numbers, not guesses: cycles, ROM bytes, stack and scratch RAM per helper and
per realistic caller. `sangoku-mt4.1` asked for a reusable command reporting
those (T-cycles only, not host time; no full GBC peripherals) for at least
`mul16` and a stack-using helper. Completed from base 7a0f9ca. Result: 33 tests
pass, and the harness immediately exposed that the existing division helpers are
wrong.

## Case

Run helpers on a small SM83 emulator and report body versus caller costs, for
example `mul16(1,1)` and the division entries `udiv16`/`urem16` with operands
1,1.

## Before

No way to execute division or measure stack/scratch. `tests/emu.py` lacked
`PUSH`/`POP`, calls/returns/jumps, `RST`, 8-bit ALU/compare/borrow instructions,
`INC` and pair arithmetic, carry/bit operations and stack-pointer adjustments.

## After

For operands 1,1, `mul16` body/caller = 484/592 clocks, 30 helper code bytes, 18
caller bytes, 4 peak stack bytes, no table or scratch allocation. The nested
stack fixture = 180/288 clocks, 24 helper code + 2 table + 18 caller bytes, 10
peak stack bytes, 4 allocated scratch bytes and 1 written byte.

Division reports intentionally exit 1: current `udiv16(1,1)` returns 256;
`urem16` returns 32201 in isolation and 27683 through the caller because of
uninitialized input state. Both are incorrect. The linked division object is 97
bytes including both helpers. These are defect reproductions, not accepted
performance candidates; runtime fixes remain under `sangoku-mt4.2.1`.

## How

- Extended `tests/emu.py` with the instructions above, plus peak-stack and
  written-address counters with explicit metric reset. Costs/flags follow the
  RGBDS gbz80 CPU manual.
- `runtime_harness.py`: RGBDS assembly, symbols, section sizes, source hashes.
- `audit_runtime.py`: helper/caller T-cycles, code/table/caller ROM,
  declared/touched scratch RAM, peak stack, results, observed register changes,
  tool versions and commands; optional artifact directories keep assembly,
  objects, ROMs, maps and symbols. See `wiki/runtime-audits.md`.
- Tests (33): exhaustive SUB/SBC/CP results/flags (262,144 cases), 622
  division-core cases with explicit `BC` dividend and `D`/`E` divisor low/high
  (seed 0), divide-zero vector handling, 10,256 multiplication pairs, control
  flow/stack tests, independent report size/stack/scratch/cycle checks. Default
  report: ten cases with correct body and caller results.

```text
python -B -m unittest discover -s tests -v
python -B tests/audit_runtime.py --output build/runtime-audit.json \
  --artifacts build/runtime-audit
python -B tests/audit_runtime.py --helper udiv16 --helper urem16 --lhs 1 \
  --rhs 1 --output build/division-audit.json --artifacts build/division-audit
```

Ruff checks/format, `cargo test --bins`, `cargo clippy --allow-dirty --fix`,
`cargo fmt` and `git diff --check` passed. No compiler or runtime source
changes.

## Alternatives

Coverage limits: flat ROM0/WRAM0, instruction subset, synthetic ABI callers.
Body stack accounting includes a preexisting 2-byte return and 2-byte argument
slot. No peripherals, interrupts, banking or bus timing; trap handler not
executed.
