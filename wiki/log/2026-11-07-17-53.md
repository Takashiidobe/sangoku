# Make the sort example fit and execute (sangoku-rj0)

_2026-11-07 17:53:13_

## Context

After the retained-formatting diagnostic (`sangoku-3kt`), `examples/sort.rs`
could not link: `sort_unstable` pulls in slice-index failure helpers whose panic
messages need `core::fmt`, so the ROM exceeded 32768 bytes even though none of
that code runs. `sangoku-rj0` (task, P1) asked for a small safe sort that avoids
panic-formatting dependencies and restores the example's execution test. The
related `sangoku-xn2` (direct serial formatting) was closed with it.

## Case

```rust
values.sort_unstable();
for place in [10000, 1000, 100, 10, 1] { /* decimal digits */ }
```

## Before

The ROM did not fit: the linker reported retained formatting and a capacity
failure, so the example could not run.

## After

The ROM uses 23869 bytes with 8899 free, prints the expected before/after
arrays, sum 3424 and maximum `Some(1999)`, returns zero and emits no formatting
warning.

## How

`examples/sort.rs` gets a bubble sort over `iter_mut()` (no indexing, no panic
paths) and borrows the decimal-place array (`for &place in &[...]`), removing
owned array iterator machinery. `tests/examples.rs` again executes the example;
the old `sort_unstable` case moved to a minimal fixture
`tests/fixtures/programs/sort_formatting.rs` so the formatting/capacity
diagnostics stay covered. Nextest CLI/example checks 13/13 including all four
example checks; clippy, fmt, LSP diagnostics and diff checks pass.

## Alternatives

Keeping `sort_unstable` in the example was dropped for size; it survives only in
the diagnostics fixture.
