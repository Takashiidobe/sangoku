# Cranelift 6d3854dd — Register Z80 in ISA lookup

_2026-11-05 08:35:43_

## Context

After `a48d255a` the Z80 ISA existed but could not be reached: callers pick a
backend by target triple, and nothing mapped a Z80 triple to it. Commit
`6d3854dd` (Cranelift fork, `third_party/wasmtime`) makes the target selectable
through Cranelift's normal target builder. No bead id is recorded.

## Case

Asking Cranelift for a Z80 target triple found no builder.

## Before

`z80 = []` in `cranelift/codegen/Cargo.toml` enabled nothing in
`target-lexicon`, and `isa/mod.rs` had no Z80 arm.

## After

```diff
-z80 = []
+z80 = ["target-lexicon/arch_z80"]
...
+#[cfg(feature = "z80")]
+Architecture::Z80(_) => isa_builder!(z80, (feature = "z80"), triple),
```

## How

`cranelift/codegen/Cargo.toml` enables target-lexicon parsing and
`src/isa/mod.rs` routes Z80 triples to the builder. The new `isa_builder` in
`src/isa/z80/mod.rs` constructs target flags (new `settings.rs`) and the
backend, and Z80 is included in `all-arch`.

## Alternatives

Using Cranelift's existing ISA-builder path lets callers select Z80 by triple
instead of through a separate target-specific entry point. No other mechanism
was compared.
