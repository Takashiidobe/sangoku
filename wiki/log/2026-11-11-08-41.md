# sangoku-61a.2.1 rustc_codegen_cranelift: archive native LR35902 objects and Rust metadata

_2026-11-11 08:41:53_

- area: cranelift/lr35902
- area: tests/archives

Outcome: Cargo target libraries now carry normalized LR35902 code in rlib and
staticlib archives, with Rust metadata and native archive symbol indexes.

## Gap and why it mattered

The working compiler path emitted RGBDS assembly without an object file. Cargo
could check metadata but could not preserve target code through normal crate
archives or reuse saved target dependencies for native code generation.

## Implementation

The rustc_codegen_cranelift CLIF-level emission adapter captures encoded
Cranelift functions, data definitions, and typed relocations as sangoku objects.
The rustc archive builder receives a native symbol reader and retains its
existing Rust metadata and archive-member manifest handling. No MIR-to-CLIF
translation or Rust fork source changed.

Local/global/weak definitions retain their linkage and original Rust names.
Codegen-unit objects remain distinct inside dependency and combined archives.
Initialized RAM pointer data retains patch bytes; zero-only RAM without
relocations becomes zero-fill storage.

The LR35902 byte encoder previously patched absolute local jumps with offsets
from zero and supplied no relocation for their final function address. It now
records absolute label relocations, resolved into function-symbol references
plus offsets by the object adapter.

## Before and after

The consumer fixture calls a non-inlined dependency and instantiates a generic:

```rust
pub fn call_dependency() -> u8 {
    dependency::identity(dependency::dependency_answer())
}
```

Before: native archive output was unavailable. An initial byte-only producer
also returned zero when its archived constant function was placed at $0200.
After: Cargo builds both crate archives, and the archived function returns 42
after relocation to that nonzero address.

## Regression and validation

The archive test verifies code, metadata, symbol indexes, multiple codegen
units, generic instantiation, cross-crate calls, runtime helper imports, and
ROM/RAM function/data pointer relocations. An unchanged Cargo build is fresh.
Copied dependency artifacts work after removing their source and target tree.
Both default Cargo split metadata and embedded-metadata rlibs are exercised; the
direct copied-artifact checks run with no programs available on PATH. All 223
default tests, 40 LR35902 tests, and seven backend unit tests passed. The
rebuilt installed driver emits archives; the hello ROM smoke build, Clippy,
formatting and diff checks passed.

Limits: native executable ROM linking and a normal no_std target sysroot remain
separate work. Assembly, TLS, custom sections, used statics and staticlib symbol
hiding/renaming are explicitly unsupported on the native object path. Default
native ROM sections currently constrain placement to Rom0; flexible placement
across both fixed windows is tracked separately.
