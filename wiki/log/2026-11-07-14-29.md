# memcpy and memmove runtime routines (sangoku-30k.9.1.6)

_2026-11-07 14:29:45_

## Context

Cranelift emits plain `call memcpy` and `call memmove` for libcalls (`rgbds.rs`
maps `LibCall(Memcpy)`/`(Memmove)` to those names), about 60 sites in `core`,
and nothing defined them: `runtime/memory.asm` only had `__gbc_memset`, and
`compiler_builtins` defines `__rust_memcpy`/`__rust_memmove` under a different
prefix. `sangoku-30k.9.1.6` (P0) preferred a fast hand-written SM83 routine for
size and speed. `memcmp`/`bcmp` come from `compiler_builtins` with the `mem`
feature (see `sangoku-30k.9.1.5`).

## Case

Any block copy in `core` lowering to `call memcpy` or `call memmove`, with
overlapping or disjoint ranges.

## Before

Link-time undefined symbols `memcpy` and `memmove`.

## After

One shared routine in `runtime/memory.asm` for both names. Arguments: `dst` in
`BC` (low `B`, high `C`), `src` low in `A` and high on the stack, `len` on the
stack; it returns `dst`.

```asm
memcpy::
memmove::
    ...                 ; dst < src ? .forward : .backward
.copy_four:             ; four bytes per iteration, entered by Duff's device
    ld a, [hli]
    ld [de], a
    inc de
```

## How

Forward copy when `dst < src` uses the Duff's-device loop from SDCC 4.6.4
`device/lib/sm83/memcpy.s` (attribution in `runtime/NOTICE`); otherwise a
backward byte loop, so overlap is correct either way. SDCC has no SM83 `memmove`
because its z80-common one uses `LDIR`/`LDDR`, which the LR35902 lacks.
`src/main.rs` and the lowered test harness link `memory.asm` when the assembly
mentions `memcpy` or `memmove`.

Tests: `tests/memory.rs` runs the routine directly over edge, overlap and random
cases against a host model and checks the return value, stack pointer and
untouched stack arguments; CLIF fixture
`tests/fixtures/emulate/memory-libcalls.clif` exercises the real lowered call
sequence. Not pushed.

## Alternatives

Speed gain over the byte loop is expected but not measured. Pointing the libcall
map at `compiler_builtins` was the other option. Decision recorded on
`sangoku-30k.9.1.5`: build `compiler_builtins` once.
