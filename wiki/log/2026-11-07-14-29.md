# memcpy and memmove runtime routines

_2026-11-07 14:29:45_

sangoku-30k.9.1.6: Cranelift emits plain call memcpy and call memmove (about 60 sites in core) and nothing defined them. Added one shared routine to runtime/memory.asm taking (dst in BC, src low in A and high on the stack, len on the stack) and returning dst. It copies forward when dst < src using the Duff's-device loop from SDCC 4.6.4 device/lib/sm83/memcpy.s (four bytes per iteration, attribution in runtime/NOTICE) and backward otherwise, so overlap is correct either way; SDCC has no SM83 memmove because its z80-common one uses LDIR and LDDR. src/main.rs and the lowered test harness now link memory.asm when the assembly mentions memcpy or memmove. Tests: tests/memory.rs runs the routine directly over edge, overlap and random cases against a host model and checks the return value, stack pointer and untouched stack arguments; a CLIF fixture exercises the real lowered call sequence. Speed gain over the byte loop is expected but not measured. Decision recorded on sangoku-30k.9.1.5: build compiler_builtins once. No push.
