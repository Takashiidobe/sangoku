# Preserve registers and flags across SM83 spills and reloads (sangoku-7em)

_2026-11-06 14:51_

## Context

Found by the popcount audit: the compiled `u16` `ctpop` reproducer returned 12
for input 0. Per the bead, at the first spill `L`/`H` hold the input, then
`ld hl,sp+0` overwrites both before they are counted; a later reload does the
same. Explicit stack instructions declared `A`/`H`/`L` clobbers, but regalloc
spill/reload edits are emitted directly after allocation in `machinst/vcode.rs`,
bypassing those operand constraints. The bug is general, not popcount-specific.

## Case

`tests/fixtures/spills/live.rs`:

```rust
pub fn audit_popcount_live(value: u16) -> u16 {
    wrapping_add(value, ctpop(value) as u16)
}
```

## Cause

`LoadStack8`/`StoreStack8` computed the stack address in `HL` (and used `A`)
without saving them, so a spill or reload while those registers held live values
destroyed them.

## Fix

In the `lr35902` backend (`inst/emit.rs`, `inst/mod.rs`, `inst/regs.rs`):
`LoadStack8` and `StoreStack8` now `push hl`/`push af` before addressing and pop
after, adjusting the requested offset by their four temporary stack bytes. Loads
into `A`/`H`/`L` replace the corresponding saved byte before restoring the
pairs; other byte loads go directly from `[HL]` into the destination. Stores
capture the original source first. No general register is reserved and the
obsolete allocator clobbers are removed.

Large stack offsets use `ld hl,imm16` then `add hl,sp`, bounding the sequences
within the declared instruction-size limit when the saves push an offset beyond
the signed-byte range. RGBDS pretty printing and native byte emission produce
identical bytes for all 126 access fixtures.

Regression: `python -B tests/check_spills.py --exhaustive16` runs the pinned
codegen tests, rebuilds the backend, compiles both Rust probes, assembles their
output and executes it in `tests/emu.py` (artifacts in `build/spill-repair`). It
enables `std,lr35902,x86` for codegen tests because a shared ISLE helper is
feature-gated to native targets; the production build path is unchanged.

All 34 targeted codegen tests and 171498 executions pass. The access matrix has
12096 executions across seven registers, load/store, nine offsets 0 to 511, all
16 flag combinations, three register patterns and two stacks, checking every
unrelated register, flags, SP restoration, four-byte peak scratch stack and
write bounds. An independent twelve-value CLIF sum and incoming stack-argument
function pass 1024 executions (B/C/A argument ABI; argument eight at stack
offset four after the return). Both Rust popcount probes pass all 65536 values
plus 13653 boundary/random/poison/alternate-stack executions each (seed 7); they
occupy 214/235 bytes, 988/1168 T-cycles including `RET`, peak stack 8/10 bytes
including the return address. All 50 unit tests and the blank ROM build pass;
Ruff, `cargo test --bins`, clippy, fmt and `git diff --check` pass. Existing
compiler warnings remain.

## Alternatives

Special-casing popcount was rejected as hiding the bug. The popcount
optimization stays separate (`sangoku-pg3`). Saving/restoring costs four stack
bytes and extra instructions per spill; cheaper spills are not attempted here.
