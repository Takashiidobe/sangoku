# Identify runtime performance audit candidates

Inspected current runtime helpers and LR35902 lowering for audit opportunities.
Priority candidates: unsigned divide/remainder and a shared divmod core;
popcount, currently expanded into sixteen bit-processing steps; wide/variable
shifts; memory copy/move/set/compare; wider multiplication; signed division;
leading/trailing zero counts and bit reversal. Audit small arithmetic inline
before choosing libcalls because ABI setup, spills, CALL, and RET add cost.

The remainder helper currently enters without the argument unpacking and
remainder initialization used by the division helper; audit correctness first.
Compare existing division alternatives only after validating their entry ABIs.

Report cycles by input class, ROM code/table bytes, caller setup bytes, peak
stack including return addresses and arguments, and owned scratch RAM. Measure
complete callers as well as helper bodies. For memory routines, vary length,
alignment, overlap, and mismatch position. No benchmarks or implementation edits
in this turn; no Bead created. Clippy/fmt passed.
