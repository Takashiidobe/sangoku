# Cranelift dadb0685 — Format instructions as RGBDS assembly

_2026-11-05 10:00:20_

## Context

The toolchain assembles with RGBDS, so the backend's output has to be RGBDS
source, and humans need to read it while debugging. Commit `dadb0685` (Cranelift
fork, `third_party/wasmtime`) replaces debug-style instruction output with an
RGBDS printer. No bead id is recorded.

## Case

Printing an accumulator operation should show the moves around the CPU
instruction, e.g. `ld a, b` / `add a, c`.

## Before

Debug-style instruction text, not assembler input.

## After

```rust
if regs::hw_enc(lhs) != a {
    lines.push(format!("ld a, {}", asm_reg(lhs)));
}
lines.push(format!("{op} {}", asm_reg(rhs)));
if regs::hw_enc(dst) != a {
    lines.push(format!("ld {}, a", asm_reg(dst)));
}
```

## How

`isa/lr35902/inst/mod.rs` (+143 lines) emits RGBDS syntax and register names
instead of relying on binary bytes or a host disassembler. Tests check forms
such as `ld a, b` / `add a, c` and stack loads/stores. This printer is the
readable assembly later consumed by the Rust adapter and RGBDS.

## Alternatives

Text assembly is the useful handoff format for RGBDS; a host disassembler was
not used.
