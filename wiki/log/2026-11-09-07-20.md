# Lower whole-byte u32 right shifts to byte moves (sangoku-dr7)

_2026-11-09 07:20:10_

## Context

Unicode `conversions::lookup` extracts the plane with `c >> 16`, which emitted
sixteen `srl` rounds plus three `rr` instructions (lookup 3,882 bytes, 213-byte
frame, in a 17,483-byte uppercase-first probe at opt `z`). `sangoku-dr7` (P2)
asked to select high bytes directly for whole-byte constant shifts, with
logical/arithmetic semantics checked. Result: entry point 208 -> 76 B, full
repro 300 -> 168 B, and the combined fixture now links.

## Case

```rust
let plane = (input >> 16) as u16;
let low = input as u16;
```

with `input` read volatile from `0xc000` (`tests/core_rom/unicode_plane.rs`).

## Currently emits

Sixteen one-bit `srl` rounds plus three `rr` for `c >> 16`; exact listing not
recorded.

## Should emit

Byte selection and zero fills instead of shift rounds. The real listing is the
`%high_half` function in `tests/fixtures/lower/ushr32-bytes.clif`; the gap is
that lookup stack/copy overhead (the 213-byte frame) remains.

## How

Whole-byte constant `u32` `ushr` lowers via virtual-register moves and zero
fills (counts mask to 31; a zero count aliases the input). Backend change in
wasmtime commit `7cf216af`, which preserves existing dirty files.

Measured: Unicode lookup 3882 -> 3733 B (frame stays 213 B); uppercase-first ROM
17483 -> 17334 B; lowercase fixture 24776 -> 24627 B; uppercase fixture 26463 ->
26314 B; combined fixture 32864 -> 32715 B, now links. Data unchanged.

Tests: volatile plane/low-half repro, and bounded emulator tests for counts
0/8/16/24 and masked counts with live inputs. Rebuilt the release backend and
target libraries. All 39 default lowering tests, four Unicode ROM tests, lower
FileCheck, hello smoke, clippy/fmt and LSP checks pass. Initial test delays were
rebuild contention; warm reruns take under 2 seconds.

## Alternatives

Not done: remaining stack/copy overhead in the lookup still needs work.
