# ROM size baseline against SDCC

_2026-11-07 20:26:28_

Added benchmarks/size_baseline.py, benchmarks/empty.rs and SDCC sm83 C
equivalents of hello/primes/sort/heap (benchmarks/sdcc). Results in
wiki/concepts/size-baseline.md; closed sangoku-30k.9.1.9.3.

- Empty program: 1286 bytes, no core; 1066 is the always-linked 32-bit runtime.
- Opt z vs SDCC: hello 6866/67, primes 22894/355, sort 18316/613,
  heap 63682/2000.
- s and z are identical: rustc only MIR-inlines at opt 2/3 and Cranelift does
  not inline. Opt 2 shrinks hello to 2259 (core 0), sort 7743, heap 32031,
  but miscompiles hello/primes/sort serial output (prints 'H', returns 0x81).
- alloc costs 21-25 KB + heap 2.7-3 KB for one Vec/Box demo vs ~1.6 KB for
  SDCC malloc/realloc/free.

Filed 30k.9.1.9.4 (opt-2 miscompile, P0), .5 (MIR inline at s/z, blocked by
.4), .6 (32-bit runtime always linked), .7 (unreferenced data sections).
No compiler changes; tests not rerun beyond the script and opt-level runs.
