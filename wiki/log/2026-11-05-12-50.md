# rustc_codegen_cranelift 3d548eb — Disable experimental float builtins

_2026-11-05 12:50:23_

## Context

The LR35902 has no floating-point hardware and the backend has no float
lowering. rustc still enables the experimental `f16`/`f128` builtins when
`has_reliable_f16_f128` is true, which would require float-bearing compiler
builtins in a 32 KB ROM. Commit `3d548eb` in `rustc_codegen_cranelift`; no bead.

## Case

`target_config` for the `z80` arch, which previously reported `f16`/`f128` as
reliable.

## Before

```rust
let has_reliable_f16_f128 = !(sess.target.arch == Arch::X86_64
    && sess.target.os == Os::Windows
    && sess.target.env == Env::Gnu
    && sess.target.cfg_abi != CfgAbi::Llvm);
```

## After

```rust
let is_lr35902 = sess.target.arch == Arch::Other("z80".into());
let has_reliable_f16_f128 = !is_lr35902 && !(/* same Windows GNU check */);
```

## How

`src/lib.rs` adds the target check to the existing feature decision. Gating, not
emulation: subsequent code skips unused float-bearing library routines and
rejects float MIR in game code (2026-11-05-13-04).

## Alternatives

Implementing the experimental float builtin path would expand the backend
substantially; this change gates it while core compilation proceeds.
