# rustc_codegen_cranelift 3d548eb — Disable experimental float builtins

_2026-11-05 12:50:23_

## Files and implementation

`third_party/rustc_codegen_cranelift/src/lib.rs` includes the LR35902 in the
existing reliability gate for f16/f128:

```diff
+let is_lr35902 = sess.target.arch == Arch::Other("z80".into());
+let has_reliable_f16_f128 = !is_lr35902
+    && !(sess.target.arch == Arch::X86_64
+        && sess.target.os == Os::Windows
+        && sess.target.env == Env::Gnu
+        && sess.target.cfg_abi != CfgAbi::Llvm);
```

This prevents rustc from enabling experimental float builtins for a target with
no floating-point lowering. The choice is to gate the feature, not emulate
floats; subsequent code explicitly skips unused float-bearing library routines
and rejects float MIR in game code.

Commit: `3d548eb` — `rustc_codegen_cranelift`.

- Purpose: Keep float-bearing compiler builtins from being required on a CPU
  without hardware float support. Change: Mark f16/f128 unreliable for the
  LR35902 target. Implementation: Add the target check to the existing
  `has_reliable_f16_f128` feature decision. Alternative: Implementing the
  experimental float builtin path would expand the backend substantially; this
  change gates it while core compilation proceeds.
