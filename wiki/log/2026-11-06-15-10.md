# Select native SM83 popcount by optimization intent (sangoku-pg3)

_2026-11-06 15:10_

## Context

The popcount audit (`sangoku-mt4.3`) showed the generic expansion of
`popcnt.i16` (sixteen AND/add/16-bit-shift steps) was far too big and slow for
an 8-bit target; the repaired compiler output was 211 bytes and 936 clocks. This
change implements the audit's YES verdict. The bead notes that the cg_clif
bridge mapped every optimized Rust level, including `s`/`z`, to
`speed_and_size`, so size intent had to be propagated separately.

## Case

`ctpop` on `u16` (and zero-extended `u32`) in Rust code built at levels
`0|1|2|3|s|z`.

## Currently emits

Sixteen generic expansions: 207 bytes in the pinned probe (see `sangoku-mt4.3`),
211 bytes/936 cycles after the spill repair. Listing not recorded.

## Should emit

One native instruction per level class: levels 1/2/3 use table-free parallel
counting; level 0 and `s`/`z` use the compact shift loop. The 12/50-byte
instruction bodies replace the generic expansions; `RET` gives the audited
13/51-byte helpers. Actual narrow Rust bodies including `RET` and CFG overhead:
level 0 uses 27 bytes/728 T-cycles, 1/2/3 use 57/248, `s`/`z` use 19/696; peak
stack is two return-address bytes. The spill-heavy two-input probe takes
166/2488, 245/1708 and 153/2436 respectively, peak stack 14 bytes. Tables:
`wiki/audits/popcount16.md`.

## How

- The compiler bridge retains unoptimized versus optimized shared flags and
  passes Rust `s`/`z` through the new LR35902 `optimize_for_size` ISA flag.
  Other targets keep their settings. The unoptimized and size cases share an
  algorithm but stay distinguishable for future decisions.
- `Popcnt16` consumes fixed `B`/`C`, produces `A`/`B`, declares `C`/`D` scratch
  clobbers (plus `E` for parallel counting). The allocator preserves live
  sources normally. Both kernels leave `HL` untouched, use no tables or private
  stack. The instruction-size bound was raised for the larger kernel. Native
  bytes match the audited RGBDS images.
- `build`/`example` accept `--opt-level 0|1|2|3|s|z` (default 0), also
  `--opt-level=z`; `cargo run -- build game.rs game.gb --opt-level 2` selects
  speed. Two CLI tests cover level/position/default handling and invalid
  options.
- Check: `python -B tests/check_popcount.py --exhaustive16`. All 35 LR35902
  codegen tests and 1918408 executions pass: four Rust probes (u16 counts,
  zero-extended u32 counts, input reuse, two counts with both inputs live) each
  run all 65536 inputs at six levels, plus seed-11 pairs, poisoned registers and
  alternate stacks. The pressure pair uses `other=(40503*input+12345)&65535`,
  not all u16 pairs. IR verification and allocation checking on; includes 12096
  stack accesses and 1024 pressure/incoming-argument checks from `sangoku-7em`.
- After formatting, all six rebuilt ROMs match the tested images byte for byte.
  50 Python tests, clippy, fmt, `git diff --check` pass; blank ROM builds pass
  at 0, 2 and z. Artifacts in `build/popcount-replacement`.

## Alternatives

Tables (byte/nibble) stay audit references, not a mandatory aligned table.
Existing compiler warnings remain.
