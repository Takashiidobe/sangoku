# rustc_codegen_cranelift e933db0 — Emit LR35902 assembly in AOT mode

_2026-11-05 10:25:57_

## Context

To build `core` for the Game Boy there must be a route from rustc to assembly
without linking a ROM or needing a runtime. Ordinary object output cannot
represent this target yet. Commit `e933db0` (`rustc_codegen_cranelift`) adds an
assembly-only AOT path. No bead id is recorded.

## Case

Compiling a crate for the target with the AOT driver produced no usable output.

## Before

No RGBDS output; the AOT driver only produced native objects.

## After

One RGBDS section per codegen unit, with exported Rust functions:

```rust
pub(crate) fn new_source(module: &str) -> String {
    format!("SECTION \"{}\", ROM0\n\n", symbol_name(&format!("cgu_{module}")))
}
writeln!(source, "EXPORT {symbol}\n{symbol}::").unwrap();
```

## How

New `src/rgbds.rs`; `src/driver/aot.rs` and `src/base.rs` pass an optional
assembly buffer through codegen-unit processing and collect the machine code's
pretty-printed instructions as RGBDS source; the `z80` target triple is
recognized. Tests: source has `EXPORT __rust__RNvCs3foo3bar`, `.block0:`,
`jr .block1`, `.block1:`; `symbol_name("a.$b") == "__rust_a_2E_24b"`; an
`rgbasm`/`rgblink` smoke test runs when installed.

## Alternatives

Assembly-only output isolates codegen from RGBDS linking and ROM runtime
requirements, which lets `core` be compiled during codegen bring-up.
