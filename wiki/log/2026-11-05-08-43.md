# Cranelift 69ab99d9 — Port Z80 scaffold to LR35902

_2026-11-05 08:43:22_

## Context

The Game Boy CPU (LR35902/SM83) is not a Z80: it lacks some Z80 instructions and
registers. A Z80-named backend would invite emitting code the hardware cannot
run. Commit `69ab99d9` (Cranelift fork, `third_party/wasmtime`) resumes the old
backend work on current Cranelift (the scaffold is based on `zlfn/cranelift-z80`
and adapted to current Wasmtime main) and restricts it to the Game Boy CPU. No
bead id is recorded.

## Case

The scaffold was named `z80` and written against older Cranelift interfaces.

## Before

`mod z80;`, feature `z80`, `"z80" => z80::define()`.

## After

```diff
-mod z80;
+mod lr35902;
...
-"z80" => z80::define(),
+"lr35902" => lr35902::define(),
```

## How

Moved `cranelift/codegen/src/isa/z80/` to `isa/lr35902/`, renamed the feature
and metadata (`meta/src/isa/lr35902.rs`), introduced LR35902 target metadata and
updated instruction, ABI, register and lowering code to current Cranelift APIs.
The triple still uses target-lexicon's `z80` architecture, while the backend
identifies the narrower Game Boy CPU. Most instruction lowering remains
unimplemented at this point.

## Alternatives

A dedicated LR35902 target avoids claiming Z80-only instructions and registers
that the Game Boy CPU does not have. Mapping a real `lr35902` triple was not
done here; the `z80` architecture string is still reused.
