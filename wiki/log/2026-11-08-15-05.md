# Native-width popcount and CLZ integration

sangoku-fx7 / sangoku-4gv: Add independent popcnt8/popcnt16/popcnt32 compact
and speed entries, selected at s/z versus 0–3. Public entries follow the backend
byte ABI: B/C/A then stack arguments, A/B/C/D returns, caller-saved registers,
caller-cleaned arguments. Native results zero their upper return bytes.

Add GbcPopcnt8/GbcPopcnt16 signatures and symbol mappings in both backends.
i8 no longer widens to i32; i16 calls native helpers at 0/s/z and retains inline
parallel counting at 1–3. The shared speed byte core takes/returns A and preserves
B/C/D/E. Speed wrappers use it once per byte; size loops remain independent.

| Width | Compact ROM / T-cycles | Speed ROM / T-cycles |
| ----- | ---------------------- | -------------------- |
| 8     | 11 / 280               | 28 / 128             |
| 16    | 15 / 672               | 37 / 304             |
| 32    | 25 / 1856              | 55 / 624             |

ROM includes the byte core for each individually linked speed entry. All three
speed widths together occupy 72 bytes, versus 120 if linked independently.
Timing covers entry through RET, excluding outer caller packing/CALL. Speed
16/32 need two extra stack bytes; speed8 tail-jumps. No scratch RAM or tables.
Sharing replaces the old 112-byte/468-cycle i32 speed helper with 55/624.

CLZ32 was already hooked up. Validate and adopt the local accumulator-shift
candidate; narrow CLZ still widens and removes padding zeros. Zero, every
single set/clear bit, alternating patterns and deterministic samples pass.
Retain original popcount proposals as tests/fixtures/popcount/candidates/.
Their byte counts are correct, but the pointer ABI adds copies, its HL pointer
is incompatible with the table routine's HL clobber, and table alignment needs
placement or explicit padding. A fixed-$400 padded table probe occupies 272
bytes; this is not an inherent cost for every possible section placement.

Validation: 36 LR35902 backend tests and 16 targeted host tests pass. Five
popcount/CLZ tests, including actual no_core Rust callers at 0/2/z, finish in
about one second together. They check signed inputs, zero extension, live
inputs, stack/argument preservation, all widths and independent linking.
Backend release and CLIF tool rebuilds pass; clippy --allow-dirty --fix,
fmt, LSP errors and git diff --check pass. Existing compiler audit linking
was adapted for native calls. The broad ROM suite was stopped at user request;
core/ROM rebuilds caused the long wait. Removed the new six-ROM test and used
small Rust probes instead. The targeted wide-ops test passed after rebuilding
the standalone CLIF tool. No Rust fork sources changed.
