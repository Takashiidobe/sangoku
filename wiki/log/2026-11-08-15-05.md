# Native-width popcount and CLZ integration (sangoku-fx7, sangoku-4gv)

_2026-11-08 15:05_

## Context

`sangoku-4gv` asked for native 8/16-bit popcount helpers so narrow popcounts
stop widening to 32 bits, keeping inline 16-bit speed lowering where useful.
`sangoku-fx7` asked to audit the pre-existing local CLZ and popcount candidates
(`runtime/bitshift/clz/common/i32.asm`, `runtime/popcnt.asm`,
`popcnt8_size.asm`, `popcnt8_opt.asm`) against the lowering, runtime registry
and emitted call symbols, and decide which are reachable or need wiring. Both
closed here. Adds independent `popcnt8`/`popcnt16`/`popcnt32` compact and speed
entries, selected at `s`/`z` versus `0`-`3`.

## Case

`count_ones` on `i8`/`i16`/`i32`, and narrow CLZ.

## Currently emits

`i8` widened to `i32` and called the 32-bit helper (the old 112-byte / 468-cycle
`i32` speed helper); `i16` used inline parallel counting at every level. The
listing is not recorded. CLZ32 was already hooked up; narrow CLZ still widens
and removes padding zeros.

## Should emit

Compact ROM / T-cycles vs speed ROM / T-cycles: `popcnt8` 11 / 280 vs 28 / 128;
`popcnt16` 15 / 672 vs 37 / 304; `popcnt32` 25 / 1856 vs 55 / 624.

ROM includes the byte core for each individually linked speed entry. All three
speed widths together occupy 72 bytes, versus 120 if linked independently.
Timing covers entry through `RET`, excluding outer caller packing/`CALL`. Speed
16/32 need two extra stack bytes; speed8 tail-jumps. No scratch RAM or tables.
Sharing replaces the old 112-byte/468-cycle `i32` speed helper with 55/624.

## How

Public entries follow the backend byte ABI: `B`/`C`/`A` then stack arguments,
`A`/`B`/`C`/`D` returns, caller-saved registers, caller-cleaned arguments;
native results zero their upper return bytes. Added `GbcPopcnt8`/`GbcPopcnt16`
signatures and symbol mappings in both backends. `i8` no longer widens to `i32`;
`i16` calls native helpers at `0`/`s`/`z` and keeps inline parallel counting at
`1`-`3`. The shared speed byte core takes/returns `A` and preserves
`B`/`C`/`D`/`E`; speed wrappers use it once per byte, size loops stay
independent. CLZ: validated and adopted the local accumulator-shift candidate;
zero, every single set/clear bit, alternating patterns and deterministic samples
pass.

Tests: 36 LR35902 backend tests and 16 targeted host tests pass. Five
popcount/CLZ tests, including actual `no_core` Rust callers at `0`/`2`/`z`,
finish in about one second together and check signed inputs, zero extension,
live inputs, stack/argument preservation, all widths and independent linking.
Backend release and CLIF tool rebuilds pass; `cargo clippy --allow-dirty --fix`,
fmt, LSP errors and `git diff --check` pass. Compiler audit linking was adapted
for native calls. The broad ROM suite was stopped at user request (core/ROM
rebuilds caused the long wait); the new six-ROM test was removed in favor of
small Rust probes. The targeted wide-ops test passed after rebuilding the
standalone CLIF tool. No Rust fork sources changed.

## Alternatives

The original popcount proposals are retained as
`tests/fixtures/popcount/candidates/` rather than adopted: byte counts are
correct, but the pointer ABI adds copies, its `HL` pointer is incompatible with
the table routine's `HL` clobber, and table alignment needs placement or
explicit padding. A fixed-`$400` padded table probe occupies 272 bytes; this is
not an inherent cost for every possible section placement.
