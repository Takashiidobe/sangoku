# rust 1d27b394 — Add LR35902 C ABI classification

_2026-11-05 13:40:26_

## Context

Compiling `core` for the custom `z80` architecture hit a panic in rustc itself:
`adjust_for_foreign_abi` in `rustc_target::callconv` ends in
`panic!("no lowering implemented for {arch}")` for any `Arch::Other`. Until
rustc could classify C-ABI arguments and returns for the target, no foreign-ABI
signature could be lowered, so `core` never reached the Cranelift backend.
Commit `1d27b394` in the Rust fork (`third_party/rust`).

## Case

Any `extern "C"` signature, or any function whose ABI goes through
`adjust_for_foreign_abi`, with the target arch set to `z80`.

## Before

```text
panic: no lowering implemented for z80
```

## After

Signatures classify. Aggregates are passed and returned indirectly; scalars stay
direct.

## How

New `compiler/rustc_target/src/callconv/z80.rs`, dispatched from
`callconv/mod.rs` on `Arch::Other(arch) if arch == "z80"`:

```rust
if arg.layout.pass_indirectly_in_non_rustic_abis(cx)
    || arg.layout.is_aggregate()
{
    arg.make_indirect();
}
```

Aggregate returns are likewise made indirect. This is rustc's foreign/C ABI
classification layer. It complements but does not replace the Cranelift
backend's own function calling convention, so it does not by itself implement
the full Rust ABI in Cranelift.

## Alternatives

Not done: the full Rust ABI for the target is still the Cranelift backend's job.
No tests are recorded for this commit.
