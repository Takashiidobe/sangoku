# rustc_codegen_cranelift b4d3ccc — Use target-width f128 comparison helpers

_2026-11-05 12:33:35_

## Context

Compiling `core` for a 16-bit-pointer target pulls in `f128` comparison
builtins. The backend picked the result type of those helpers with a
compile-time constant derived from the host (`cfg(target_pointer_width)` of the
machine running rustc), so the signature was wrong for the Game Boy target.
Commit `b4d3ccc` in `rustc_codegen_cranelift`; no bead.

## Case

An `f128` `fcmp` (`__eqtf2`, `__netf2`, ...) when cross-compiling.

## Cause

`src/compiler_builtins.rs` defined `CMP_RESULT_TY` as `I64` on 64-bit hosts,
`I32` on 32-bit hosts or AArch64, regardless of the codegen target.

## Fix

`src/codegen_f16_f128.rs` selects the type from the target in `fcmp`, and the
global constant is removed:

```rust
let cmp_result_ty = if matches!(fx.tcx.sess.target.arch, Arch::AArch64 | Arch::Arm64EC) {
    types::I32
} else {
    fx.pointer_type
};
```

Both the helper call and the zero comparison use `cmp_result_ty`. No dedicated
regression test is recorded.

## Alternatives

Floats are not implemented for LR35902 here; later commits exclude float
routines from LR35902 core/game code (2026-11-05-12-50, 2026-11-05-13-04)
instead of implementing floating-point support.
