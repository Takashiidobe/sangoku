# Cranelift 6b0dd373 — Add direct calls and stack arguments

_2026-11-05 11:12:29_

## Context

The initial ABI was register-only: the byte ABI has seven byte registers, and
anything larger (a wider integer, more arguments) failed with "LR35902
register-only ABI supports up to seven byte parts". Ordinary Rust code calls
functions with more than seven bytes of arguments, so calls had to spill to the
stack. Commit `6b0dd373` in Cranelift (`third_party/wasmtime`); no bead.

## Case

A direct call with an eight-byte argument list, and a callee reading an incoming
stack argument.

## Before

```text
LR35902 register-only ABI supports up to seven byte parts
```

`compute_arg_locs` returned `Ok((0, None))`; no call instruction existed and
stack loads/stores panicked on offsets that did not fit `i8`.

## After

`compute_arg_locs` assigns overflow byte parts to `ABIArgSlot::Stack` and
returns the total as `next_stack`:

```rust
let stack_arg_space = self.lower_ctx.sigs()[sig].sized_stack_arg_space();
self.lower_ctx.abi_mut().accumulate_outgoing_args_size(
    stack_ret_space + stack_arg_space
);
Inst::CallKnown { info }
```

## How

`abi.rs`, `lower.isle`, `inst.isle` and `inst/` add `Inst::CallKnown` with call
metadata, and an emitter that records an absolute 16-bit call relocation (the
JIT and object backends gained matching relocation handling). `gen_load_stack`
and `gen_store_stack` now produce `LoadStack8`/`StoreStack8` with a
`StackAMode`. Tests cover an eight-byte-argument call and reading an incoming
stack argument.

## Alternatives

Not done: stack return values are rejected ("LR35902 stack return values are not
supported"), and indirect and tail calls remain unsupported.
