# sangoku-e6w cranelift: cheaper LR35902 byte spills with dead A

_2026-11-10 09:57:38_

- bead: sangoku-e6w
- kind: bug
- area: cranelift
- area: wiki/concepts/regalloc.md

Outcome: LR35902 stack spills omit AF saves when A is dead.

## Symptom

Byte stack loads into H or L saved AF even with no live A. Byte stores from H or
L also saved AF while preserving HL. Pressure kernels paid for redundant
push/pop pairs.

## Reproducer

Use the stored pressure and pressure16 register allocation kernels. The former
was 66 bytes and the latter was 182 bytes. Both force byte spills with live
halves of HL.

## Cause

This is CLIF-level machine instruction emission in Cranelift. It is not
MIR-to-CLIF translation in rustc_codegen_cranelift. LoadStack8 preserves the
other half of HL through A. StoreStack8 copies H or L through A before
addressing the stack. Those branches did not consult A liveness.

## Fix

Consult the existing post-instruction A liveness. Keep AF preservation when A is
live or liveness is unknown. Adjust SP-relative offsets for the omitted push.
Keep assembly text consistent with native machine bytes. Retain invocation-local
stack storage for recursion and reentry.

## Regression

Existing liveness tests now assert that dead A has no AF save. They check the
initial emitted opcode on the affected paths. The emulator checks live
registers, stack balance and memory. The harness also compares native bytes
against RGBDS output. All 39 LR35902 backend tests pass. The spill harness
passes 12096 conservative accesses. It passes 1344 liveness accesses and 1024
pressure executions. The release backend rebuild and hello ROM smoke check pass.
The default nextest suite passes all 212 selected tests. Clippy, formatting and
LSP error diagnostics pass.

Before: pressure 66, pressure16 182, sum_u16 117 bytes. After: pressure 64,
pressure16 178, sum_u16 115 bytes. No benchmark kernel grew; the stored baseline
records these results.

Limits: live HL still requires stack preservation. Static and HRAM slots need an
ownership and allocation scheme. See: sangoku-otw and wiki/concepts/regalloc.md.
