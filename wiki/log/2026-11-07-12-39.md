# Distinguish formatting compilation support from ROM usability (sangoku-30k.5)

_2026-11-07 12:39:10_

## Context

`sangoku-30k.5` (P0) found that the fork's `fmt/num.rs` replaced wide integer
formatting with `impl_unsupported_wide_fmt` on z80. It asked to restore
`u128`/`i128` `Display`/`Debug`/`Hex`/`Binary` and `f32`/`f64` (Grisu/Dragon) so
formatting matches upstream, even if slow. The user then clarified the scope:
keep expensive APIs enabled, allow them to compile, and document the paths that
are not realistically usable on this hardware instead of forcing everything to
fit. Rust `core` stays upstream-identical.

## Case

Upstream `u64`, `u128`, `f32` and `f64` decimal formatting, built with
`optimize_for_size` and `immediate-abort`, linked into a flat 32 KiB ROM.

## Before

Wide formatting was stubbed out in the fork. The backend also could not emit
read-only data, branch tables or a split-ABI `memset`, and wide scalars were not
aligned to the two-byte stack ABI.

## After

Upstream `u64` decimal formatting matches host results through `u64::MAX` in the
emulator. Measured sizes (size-optimized immediate-abort audit):

```text
u64 probe, linked image   32,174 bytes (includes 257 reserved bytes)
u128 code sections alone  190,151 bytes
f32  code sections alone  426,247 bytes
f64  code sections alone  437,126 bytes
```

So `u128`/`f32`/`f64` formatting exceeds the flat 32 KiB ROM by code alone. They
reach RGBDS emission, but runtime execution is unvalidated, and general
`println!` has no output runtime. Compilation, linking, execution and output
device limits are documented separately in `wiki/concepts/practical-limits.md`,
with a reproducible opt-in audit (`tools/audit_formatting.py`) and snapshot
(`tests/coverage/formatting-costs.json`). Wide arithmetic is not categorically
impractical.

## How

Bounded core formatting compilation and size probes (`tests/formatting.rs`),
without modifying Rust `core`. Backend work (wasmtime `a65daede`, cg_clif
`78d2ad2`): read-only RGBDS data emission, executable branch-table text
lowering, a split-ABI `memset` helper in `runtime/memory.asm`, two-byte
alignment for ordinary wide scalars (affected fixture refreshed), and full
toolchain rebuilds now clear cg_clif artifacts so a stale custom-rustc
dependency is not reused. All 114 nextest tests, clippy, fmt, Python lint and
the blank-ROM smoke pass. Not pushed.

## Alternatives

Not done: executing `u128`/`f32`/`f64` formatting, and an output runtime for
`println!`. Replacing the upstream formatting code or hiding the APIs was
rejected by the user's clarification.
