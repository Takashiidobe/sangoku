# Halting panic handler

_2026-11-07 15:40:00_

sangoku-30k.9.1.7: -Cpanic=abort only removes unwinding; core still calls the panic handler symbol rust_begin_unwind, so the runtime must define it. Added runtime/panic.asm: di, then a halt/nop/jr loop that never returns and ignores its PanicInfo argument (no formatting pulled into the ROM). src/main.rs and the lowered test harness link it when the assembly references rust_begin_unwind without defining it, so a user #[panic_handler] still wins. The test emulator gained DI (no-op) and HALT (pc stays). tests/panic.rs enters the handler with a return address on the stack and checks that it never returns, reaches the loop and leaves the stack alone. An end-to-end panicking Rust fixture is not possible yet because linking core waits on sangoku-30k.9.1.8 (per-function sections). Optional debug-port message output is left out. No push.
