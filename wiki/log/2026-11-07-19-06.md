# Track shared wide runtime and finish overflow multiplication (sangoku-57q.4.3)

_2026-11-07 19:06:47_

## Context

After the compact unsigned u128 multiply (`sangoku-57q.4.2`) signed i128 still
used the oversized `compiler-builtins` `mulo`. The user also asked for a shared
target runtime across i64/u64/f64/i128/u128/f128, because repeated inline
expansions do not fit 32 KiB. `sangoku-57q.4.3` (task, P0) asked for signed and
unsigned 64/128-bit overflow multiplication through shared helpers.

## Case

Signed and unsigned `overflowing_mul` at 64 and 128 bits, plus the 12 integer
types' methods.

## Before

Signed i128 went through `compiler-builtins`; broad combined wide-method clients
were oversized.

## After

Target-owned helpers, 292 bytes total: a 122-byte unsigned core and a 170-byte
signed wrapper. Standalone 0/`z` ROM probes pass. Broad combined wide-method
clients remain oversized and motivate the follow-up epic `sangoku-57q.10`.

## How

Magnitude, sign and range work stays in assembly because it avoided the
oversized wide-SSA expansion found during implementation; i64/u64 widen operands
and check high limbs against zero/sign extension. Signed/unsigned runtime
host-reference tests check products, flags, unchanged inputs, output bounds and
stack restoration. Added Rust method snapshots for all 12 integer types and
core-driver coverage, a mapped-libcall/provider inventory (34 symbols) and
runtime selector tests, and corrected the `memcmp` symbol mapping. Documented
that enum coverage is distinct from raw frontend math fallbacks. 163 nextest
tests plus the separate core-report test pass; clippy, fmt, diff checks and
hello ROM build pass.

## Alternatives

Created `sangoku-57q.10` for the shared runtime direction, linking existing
arithmetic-sharing, float caller-copy and ROM-size work and adding shift/
bit-method, float/conversion fallback and simple-operation measurement tasks.
`sangoku-57q.4` and `.5` stay open behind it.
