# min/max/abs and a signed compare bug (sangoku-7qz.4)

_2026-11-06 23:40_

## Context

`smin`/`smax`/`umin`/`umax`/`iabs` were missing at `i8`/`i16`/`i32` (`umax` only
for narrower types), as were `i8` `bnot` and `select`. sangoku-7qz.4 (P0)
required no unsupported matrix entries for these. Writing the emulator test for
them exposed a wrong signed comparison that affected every signed `icmp`.

## Case

Signed `i8`/`i16` compare of two same-sign operands (and the high byte of
`i32`).

## Cause

The signed `Compare8`/`Compare16` setup used `and $80`, so same-sign operands
were decided by the sign bit alone. Found by the new emulator test.

## Fix

Now `xor $80` (flip sign bits, then compare unsigned). One arm lowers `smin`/
`smax`/`umin`/`umax` at `i8`/`i16`/`i32` via `lower_compare` + `select_by_flag`
(shared with `select`, which now covers `i8`). `iabs` is `(x ^ s) - s` with `s`
from `SignFill8`. `i8` `bnot` added. Test: `tests/lowered.rs`
`min_max_abs_match_host`, fixture `tests/fixtures/emulate/min-max-abs.clif`;
edge values plus 12 seeded LCG samples per width, compared with host
min/max/abs.

## Alternatives

Not checked: preservation of unrelated registers, only the result registers.
