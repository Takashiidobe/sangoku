# Legalize i128 into four i32 limbs (sangoku-7qz.24)

_2026-11-06 22:17:25_

## Context

After `i64` was split into two `i32` halves (sangoku-7qz.9.1), `u128`/`i128`
were still unsupported. sangoku-7qz.24 (P0) generalized the legalizer to four
low-to-high `i32` limbs while keeping `i64` behavior and keeping code within the
32 KB ROM limit.

## Case

```rust
fn mul(a: u128, b: u128) -> u128 { a.wrapping_mul(b) }
```

## Before

`i128`/`u128` unsupported.

## After

Four-limb values flow through signatures, control flow, calls, returns, memory
and conversions. All 97 nextest tests pass, including none/speed host-reference
emulator checks and Rust `u128` memory ops through CLIF and RGBDS. `u128`
addition and multiplication ROMs build at opt levels 0/2; blank and `u64` smoke
builds pass.

## How

- Carry/borrow arithmetic, checked add/sub, comparisons, counts and reordering.
- To bound ROM size, wrapping multiplication uses a bounded 128-step loop and
  shifts/rotates use at most 127 steps.
- Integer-only ROM builds now omit unused soft-float helpers.

## Alternatives

Not done: native `i128` arithmetic, tracked by sangoku-7qz.9.3. Ordinary Rust
floating MIR remains blocked by the existing frontend gate.
