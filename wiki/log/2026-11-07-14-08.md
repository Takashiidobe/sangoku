# Realign over-aligned stack slots on LR35902 (sangoku-30k.9.1.2)

_2026-11-07 14:08:59_

## Context

The last two `core` lowering failures (`mem::forget<io::error::Custom>` and a
second function) were `repr(align(4))` locals failing with
`stack slot alignment of 4 bytes is larger than the stack alignment of 2 bytes`.
The bead (P1) offered clamping the slot alignment to 2 or raising the declared
stack alignment.

## Case

```rust
#[repr(align(4))]
pub struct Aligned { a: u16, b: u16 }

#[inline(never)]
pub fn take(x: Aligned) -> u16 { x.a }
```

## Cause

`cg_clif` passed the type's 4-byte alignment to Cranelift, whose LR35902 stack
alignment is 2. Clamping would break Rust's alignment guarantee for the type.

## Fix

`create_stack_slot` in `cg_clif` now treats 2 bytes as the Z80 ABI alignment and
uses its existing dynamic-realign path: over-allocate the slot, then align the
address at run time. Core non-generic probe is now 3235/3235 lowering. Added
`tests/fixtures/core/over-aligned-slot.rs` and the lowering test
`over_aligned_stack_slots_lower_through_the_backend`; it fails on the previous
backend.

## Alternatives

Not checked: the test only covers lowering, not that the realigned address
executes correctly in the emulator. Generic instantiation coverage is still
`sangoku-30k.9.1.3`. Not pushed.
