# Route f16 arithmetic through existing target converters (sangoku-57q.4.1)

_2026-11-07 18:33_

## Context

`sangoku-57q.4.1` (bug, P0): `tests/fixtures/clif/wide-float16.rs` produced
valid CLIF but the ROM failed to link. A full soft-float `compiler-builtins`
conversion is far too big for a 32 KiB cartridge, and the target already ships
f32 helpers.

## Case

`f16` add, sub, mul, div and comparisons in `wide-float16.rs`.

## Cause

cg_clif's f16 arithmetic wrappers called out to `__rust___extendhfsf2` and
`__rust___truncsfhf2`, which the target does not provide: undefined symbols at
link time.

## Fix

In `src/codegen_f16_f128.rs` of the cg_clif backend, `f16_to_f32` and
`f32_to_f16` take an LR35902 (`z80` arch) early path:

```rust
return fx.bcx.ins().fpromote(types::F32, value);   // f16_to_f32
return fx.bcx.ins().fdemote(types::F16, value);    // f32_to_f16
```

so the existing `softfloat32` helpers are reused. The fixture now covers add,
sub, mul, div, comparisons, subnormals, signed zero, infinity/NaN and ties-even
rounding, and executes instead of expecting a linker failure
(`tests/frontend_epic.rs`); README and `wiki/concepts/frontend-fixtures.md`
updated. cg_clif rebuilt first. Full nextest: 149 passed plus one
snapshot/source mismatch; regenerated sequentially, then all 12 affected
frontend/FileCheck checks pass. Clippy, fmt, diff checks and hello ROM build
pass.

## Alternatives

Backend LSP was unavailable (pinned toolchain lacks rust-analyzer); root test
diagnostics are clear.
