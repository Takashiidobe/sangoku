# Regalloc head-to-head harness against SDCC

_2026-11-09 14:05:33_

## Context

Rust-compiled kernels were 2-5x the size of SDCC `sm83` output, so we audited
five hand-written kernels (`sum_u8` 100 vs 19 bytes, `max_u8` 100 vs 20, `fill`
47 vs 15, `pressure` 66 vs 34, `mix16` 66 vs 56). The audit is sangoku-otw
(epic); this change is sangoku-e8v, the harness that makes every later fix
measurable against a stored baseline. Most of the gap is lowering, not
`regalloc2`, so the audit was filed as child issues, one per loss.

## Case

The same small kernels written in Rust (`kernels.rs`) and C (`kernels.c`),
compiled by this backend and by `sdcc -msm83 --opt-code-size`, and compared by
bytes and instruction mix.

## Currently emits

Baseline bytes from the first run, 12 kernels (the original log said 11):

```text
kernel      rust  sdcc  ratio
strlen16      83    10   8.30
copy_u8      131    18   7.28
sum_u8       100    19   5.26
max_u8       100    20   5.00
count_eq      99    25   3.96
sum_u16      133    42   3.17
fill          47    15   3.13
sat_chain    143    68   2.10
pressure      66    34   1.94
pressure16   182    95   1.92
fib16         40    24   1.67
mix16         66    56   1.18
total       1190   426   2.79
```

Where the bytes go:

- Lowering: pointers copied into `HL` for every load; `p.add(1)` and `n -= 1` go
  through `A` instead of `inc`/`dec`; compares build a boolean from a raw `db`
  run before branching; `jp` where `jr` fits.
- Allocator and ABI: a reload while `HL` is live costs `push hl` / `ld hl, sp+N`
  / `ld r, [hl]` / `pop hl`, because `abi.rs` gives `regalloc2` no scratch
  register and only SP-relative one-byte slots; also back-edge and entry spills
  in loops, and `ld d, d`.

## Should emit

Not a code target but a measurement target: each fix should move one kernel
toward SDCC and show up in `benchmarks/regalloc_baseline.json`. Opt `2` and `z`
are identical on purpose, since size needs aggressive inlining (sangoku-4we).

## How

- `benchmarks/regalloc/kernels.{rs,c}`: same-named kernel pairs.
- `benchmarks/regalloc_baseline.py`: bytes via `rgbasm`/`rgblink` (Rust) and
  `sdasgb -l` (SDCC), plus `insns`, `moves`, `stack` and `jp` counts. `--check`
  diffs against `benchmarks/regalloc_baseline.json` and fails if bytes grow;
  `--update` rewrites it.
- `wiki/concepts/regalloc.md` documents the workflow and findings.
- Children filed from the audit: dq5 (`BC`/`DE` loads), 2mv (`inc`/`dec`), i70
  (fused compare + branch), 2ea (`jr` / layout), e6w (cheaper spills), 1de (loop
  shuffles), 98d (moves via `A`), 21y (rotates).

## Alternatives

- Static bytes only: no dynamic cycle counts yet, and nothing is executed in the
  emulator.
- No `nextest` wrapper, because the harness needs `sdcc` installed.
