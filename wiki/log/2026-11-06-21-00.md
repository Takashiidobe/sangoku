# Fix i32 load/store regalloc crash

Issue sangoku-7qz.16. The coverage matrix showed load.i32/store.i32 panicking in
register allocation (SSA error). The i32 arms of Opcode::Load/Store in
cranelift lr35902 lower.rs emitted four LoadMem8/StoreMem8 instructions that
shared one scratch_h/scratch_l/accumulator vreg trio. Those operands are early
defs, so the second instruction redefined a vreg: not SSA. Each byte now gets
fresh temporaries.

Regression coverage: tests/fixtures/lower/load-store-i32.clif (FileCheck on the
emitted assembly) and tests/lowered.rs, which lowers
tests/fixtures/emulate/load-store-i32.clif, assembles it with rgbasm/rgblink and
runs it in the emulator (load returns the four bytes in A,B,C,D; store of
0x12345678 writes 78 56 34 12 and nothing beyond). Matrix regenerated: no
backend crashes remain.

The emitted code is poor (push/pop around spill slots per byte); that is
register-pressure work, not part of this fix. LSP (rust-analyzer) needs a few
seconds to answer and returned nothing for the first queries; use it with a
short wait. Its diagnostics show old unused-import warnings in lr35902.
