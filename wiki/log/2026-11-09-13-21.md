# Share wide shifts and rotates through size/speed libcalls (sangoku-57q.10.1)

_2026-11-09 13:21:23_

## Context

Variable `i64`/`u64`/`i128`/`u128` shifts and rotates expanded inline in the
`lr35902` legalizer; `sangoku-57q.10.1` (P0, part of the compact wide-ops epic
57q.10) asked to route them, and the wide bit methods, through shared compact
loops. This is part 1: shifts and rotates. Rust probe callers shrink from
1.6-4.8 KB to 0.37-0.69 KB at opt 0 and `z`.

## Case

Any variable `<<`, `>>`, `rotate_left`/`rotate_right` on 64- or 128-bit ints.

## Currently emits

Inline limb expansion per use (1.6-4.8 KB per probe caller). At opt 0, `u128`
had no terminal helper and `u16`/`u32`/`u64` reached `__gbc_shift16`.

## Should emit

A call to `__gbc_shift64`/`__gbc_shift128` with an in-place memory ABI (value,
op byte, count). Levels `s`/`z` link a one-bit loop (81 B per width); levels 0-3
link byte moves plus <=7 bit steps (211/259 B) via private bit/byte step
objects.

## How

- Removed the unused inline shift/shift128; new `LibCall` variants in wasmtime
  and cg_clif maps.
- Tests: `wide_shift` (direct helper vs host at 12 counts x 4 values x 5 ops,
  size and opt; Rust probes at 0/`z`), link selection unit test, `lowered`
  harness links the helpers. Default suite 209 pass, extensive wide-int checks
  pass, intrinsics audit regenerated (also picks up older drift).
- Fixed a core build race: `core_libraries` takes an exclusive per-opt-level
  file lock and rechecks freshness. One core per opt level is by design (6 x ~75
  MB); the large dirs are `target/debug` (6.9 GB) and `build/artifacts` (3752
  per-run dirs, 1.2 GB).
- Committed pre-existing clippy cleanups in wasmtime.

## Alternatives

Not done: wide `clz`/`ctz`/`popcnt`/`bitrev` are still per-limb calls; `bswap`
stays free limb moves.
