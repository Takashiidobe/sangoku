# Byte loads/stores through DE (sangoku-dq5)

_2026-11-09 14:17:04_

## Context

The regalloc audit against SDCC (sangoku-otw, harness sangoku-e8v) found that
every pointer load copied the pointer into `HL` before using it, which
duplicated the pointer and doubled pair pressure. SDCC loads through `[de]`
directly. sangoku-dq5 makes byte loads/stores at offset 0 use `[de]`. Harness
total 1190 -> 1153 bytes (2.79x -> 2.71x of SDCC): `strlen16` 83 -> 64, `max_u8`
100 -> 78, `fill` 47 -> 43, `copy_u8` 131 -> 130. `count_eq` 99 -> 104 and
`sum_u8` 100 -> 104 got worse, because the `p.add(1)` / `n -= 1` sequences
(sangoku-2mv) and the fixed-register compare `db` run (sangoku-i70) now collide
with the pinned `A`/`DE`.

## Case

A byte read or write through a pointer argument, e.g. `*p` in `max_u8`, `fill`
or `strlen16`.

## Currently emits

```asm
ld h, b
ld l, c
ld a, [hl]
```

## Should emit

```asm
ld a, [de]
```

Stores are `ld [de], a`.

## How

`LoadMem8`/`StoreMem8` with offset 0 (`inst/emit.rs`, `inst/mod.rs` in the
`lr35902` backend). The pointer is fixed to `D`/`E`, the load result is fixed to
`A` and the store source is fixed to `A`, so there are no `H`/`L`/`A` early-def
clobbers and no `ld h,b; ld l,c` copy.

`DE`, not `BC`: the byte ABI passes a 16-bit argument as low = `B`, high = `C`,
the reverse of hardware `BC`, so `[bc]` loads would swap every pointer argument.

Tests: snapshots `load-store-i32.clif` and `stack-liveness.clif` regenerated
(fewer spills, intended). New emulator test
`pointer_loops_load_and_store_through_register_pairs` runs
fill/copy/max/count/strlen at opt `0`/`2`/`z` and expects 68. Full default
`cargo nextest` (209) passed except the two stale snapshots, now updated. The
`extensive` profile was not rerun.

## Alternatives

Not done: 16-bit accesses, nonzero offsets and `BC`/`HL` pairs still use the old
`HL` path, and a pointer used at offset 0 and elsewhere is swapped `DE` <-> `BC`
(follow-up sangoku-otw.1). The bead also suggested `[bc]` and `[hl+]`/`[hl-]`
forms; `[bc]` is ruled out by the ABI note above.
