# Byte loads/stores through DE (sangoku-dq5)

_2026-11-09 14:17:04_

sangoku-dq5: LoadMem8/StoreMem8 at offset 0 now emit ld a,[de] / ld [de],a (inst/emit.rs, inst/mod.rs in the lr35902 backend). Operands: pointer fixed to D/E, load result fixed to A, store source fixed to A; no more H/L/A early-def clobbers or ld h,b; ld l,c copy. Chose DE over BC because the byte ABI passes a 16-bit arg as low=B, high=C, the reverse of hardware BC, so BC loads would swap every pointer arg. Harness total 1190 -> 1153 bytes (2.79x -> 2.71x of SDCC): strlen16 83->64, max_u8 100->78, fill 47->43, copy_u8 131->130, but count_eq 99->104 and sum_u8 100->104 because p.add(1)/n-=1 (2mv) and the fixed-register compare db sequence (i70) now collide with pinned A/DE. Snapshots load-store-i32.clif and stack-liveness.clif regenerated (fewer spills, intended). New emulator test pointer_loops_load_and_store_through_register_pairs runs fill/copy/max/count/strlen at opt 0/2/z, expects 68.
