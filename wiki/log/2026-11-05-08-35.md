# Cranelift a48d255a — Initialize Z80 ISA scaffold

_2026-11-05 08:35:12_

## Context

Rust `core` has to reach the Game Boy through some code generator. The plan is
`rustc_codegen_cranelift` driving a Cranelift backend, but Cranelift has no
8-bit target. Commit `a48d255a` (Cranelift fork, `third_party/wasmtime`) starts
that backend: a `z80` feature, ISA metadata, target settings and a backend
module. No bead id is recorded for this commit.

## Case

There was no way to name the target at all: Cranelift did not know a Z80 ISA, so
nothing could be selected, let alone compile a function.

## Before

No `z80` feature, no ISA entry in the meta crate, no `isa/z80` module.

## After

The target is registered and a `TargetIsa` skeleton exists, but it lowers
nothing. `compile_function`, settings and section output are `todo!()`.

```diff
+z80 = []                          # cranelift/codegen/Cargo.toml
+mod z80;                          # cranelift/codegen/meta/src/isa/mod.rs
+    Z80,
+    "z80" => Some(Isa::Z80),
```

## How

Files: `cranelift/codegen/Cargo.toml`, `meta/src/isa/mod.rs`,
`meta/src/isa/z80.rs` and `src/isa/z80/mod.rs`, which implements the backend
interface with most codegen methods left as `todo!()`. This commit registers the
target; it does not yet lower a single function.

## Alternatives

This was a generic Z80 starting point. The commit records no comparison with
adding a dedicated LR35902 target (that came later, in `69ab99d9`).
