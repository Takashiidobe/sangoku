# Bounded native-width multiplication (sangoku-mt4.10, .1, .2)

_2026-11-08 15:40_

## Context

`sangoku-mt4.10` (epic) asked for native-width wrapping multiplication helpers
for `i8`/`i16`/`i32` with independently selected size and speed variants, wired
into the compiler/backend call paths. The user explicitly re-scoped it to a few
correctness cases and size/performance implementations, replacing the original
extensive SDCC comparison; no exhaustive or random audit ran.

## Case

Wrapping `i8`/`i16`/`i32` multiply (`a * b`); signed and unsigned share code.

## Currently emits

`i8` wrapping multiplication was widened before the call (it "now calls
`__gbc_mul8` without widening"); the listing is not recorded. The existing
compact `i16`/`i32` algorithms were the only variants.

## Should emit

`i8` calls `__gbc_mul8` directly (new `GbcMul8`, native `(i8,i8)->i8` signature,
both runtime symbol mappings). `GbcMul16`/`GbcMul32` select their width's
runtime variant.

```text
width  size bytes  speed bytes  size / speed cycles, max x max
8      13          50           344 / 212
16     30          171          912 / 672
32     108         236          12060 / 10208
```

Cycles: helper entry through `RET`, excluding caller packing/spills/`CALL`. The
speed label is a tradeoff, not a win on every input: `i32` 1x1 costs 776 compact
cycles versus 1424 unrolled; zero costs 412 versus 416. `i8`/`i16` allocate no
stack, `i32` allocates eight bytes, and all use zero tables or scratch RAM.
Public helpers may clobber all general registers and flags.

## How

Retain the existing compact `i16`/`i32` algorithms and add a compact native `i8`
loop. Speed `i8`/`i16` unroll all steps and speed `i16` keeps the eight-bit
right-operand shortcut; speed `i32` unrolls four steps between termination
tests. Common `.inc` files share step definitions without extra helper
dependencies. `s`/`z` select size, `0`-`3` select speed, one object per
referenced width. No Rust fork or `compiler-builtins` changes. Compatibility
harnesses retain compact `mul16` for old measurements; production selects from
the family registry.

Tests: eight explicit operand pairs per width (zero in either position, 1x1, max
x max, high-bit overflow, mixed patterns, narrow operands in either position);
both variants match host wrapping results and preserve stack/args. Tiny
`no_core` Rust fixtures at `0`/`z` check signed/unsigned native calls and live
inputs on six pairs; no core or complete application ROM was built. 14 focused
linkage/multiplication tests pass in 1.28 seconds, the final two in 0.17
seconds; all 36 LR35902 backend unit tests and the historical compact `mul16`
caller/size/cycle regression pass. Pinned release backend rebuilt;
`cargo clippy --allow-dirty --fix`, fmt, LSP diagnostics and diff checks pass.
Reproduce: `cargo nextest run --no-fail-fast -E 'binary(multiply)'`.

## Alternatives

No exhaustive/random audit and no SDCC comparison, by user decision.
