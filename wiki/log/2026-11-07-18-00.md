# Build core and programs with debug assertions off (sangoku-4mv)

_2026-11-07 18:00_

## Context

At opt-level 0 rustc turns on debug assertions, which also enables overflow
checks and the `ub_checks` `precondition_check` functions. Those pull panic
paths through `core` and overflowed `ROM0` on the `examples/primes.rs` repro.
Filed along the way: `sangoku-4mv` (bug, P2), a wrong result from the repro.

## Case

```rust
unsafe { composite.get_unchecked(2..) }.iter().filter(|&&b| !b).count() as u8
```

## Before

`-Cpanic=abort`, `-Cpanic=immediate-abort`, and either with
`-Coverflow-checks=off` all fail with a `ROM0` placement error.

## After

`-Cdebug-assertions=off` alone links and runs. `immediate-abort` and
`overflow-checks=off` are not needed. The repro still links but returns 48
instead of 15 and emits junk serial bytes (`vwxyz{|}~...`), filed as
`sangoku-4mv`.

## How

`rustc_command` in `src/main.rs` adds `-Cdebug-assertions=off` next to
`-Cpanic=abort`. `examples/hello.rs` and `examples/primes.rs` now avoid
formatting and panicking paths (`write_str` and a hand-written `write_u8`
instead of `writeln!`, `get`/`get_mut` instead of indexing); `ufmt` added as a
dev-dependency. `tests/fixtures/mir/add.rs` adjusted. Consequence: overflow in
user code wraps silently. `build/core` is not keyed on flags, so
`rm -rf build/core` after changing them. No push.

## Alternatives

`immediate-abort` was left out because it would bypass the `__gbc_panic`
handler. The wrong result of the repro is not fixed here.
