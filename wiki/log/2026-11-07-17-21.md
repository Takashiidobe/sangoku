# Fix primes stack corruption

_2026-11-07 17:21:48_

## Context

The `primes` example produced garbage serial output and returned a wrong count.

## Case

`examples/primes.rs`: a 141-byte `main` frame plus iterator calls on the stack,
which started at `$FFFE`.

## Cause

The stack grew down from `$FFFE` into the `$FF00` I/O region, so stack writes
landed on `$FF01`/`$FF02` (serial registers) and produced garbage output. The
example also counted from the wrong index.

## Fix

Startup (`rom/header.asm`) and the ROM emulator harness (`src/main.rs`,
`tests/core_link.rs`) stacks move to `$E000` so they grow into work RAM. The
example now counts noncomposites from index 2 and returns that count. Work-RAM
stack checks were added to the example regressions in `tests/examples.rs`. No
compiler or array implementation change was needed.

Validation: primes prints 15 primes and returns 15; hello ROM builds. Clippy,
fmt, and LSP diagnostics pass. Nextest: 130/131 pass.
